1. Um laço precisa de trabalho, estado e progresso

Repetição não é apenas escrever uma linha muitas vezes. O programa mantém um estado, testa se ainda deve continuar e faz uma atualização que aproxima o término. Antes de escolher for ou while, descreva o que uma passagem representa: um aluno lido, um elemento somado, uma tentativa descartada ou uma opção de menu processada. Essa unidade torna a contagem e a revisão mais claras.

Este capítulo parte das condições e dos tipos já estudados. Ao terminar, você deverá rastrear a ordem de execução, escolher uma sentinela sem confundi-la com um dado válido, evitar divisões quando não houve itens e reconhecer um laço que não progride. Não basta obter a soma correta para três entradas: é necessário explicar como o algoritmo reage a zero entradas, a uma entrada inválida e ao fim do arquivo.

No Playground, a entrada já está escrita quando o programa começa. Um Scanner local pode esperar pelo teclado; no navegador deste guia, você fornece todas as linhas previamente. Uma operação de leitura não é uma instrução para continuar esperando indefinidamente por uma resposta que a interface não oferece. Inclua a sentinela quando a regra exigir e trate também o fim da entrada.

2. Repetir uma tarefa com uma condição de saída

Laços executam instruções repetidas vezes. Para acompanhar um laço, identifique o estado inicial, a condição de continuidade, as operações do corpo e a atualização que permite chegar ao fim. Um contador acompanha a posição ou o número de repetições; um acumulador agrega valores. Na média da turma, o contador indica qual aluno está sendo processado e o acumulador soma as médias.

O tipo de laço deve ajudar a ler o problema. for costuma reunir bem inicialização, limite e atualização quando há uma contagem; while destaca a permanência em um estado; do / while executa o corpo antes da primeira verificação. É possível reescrever várias tarefas com formas diferentes, desde que a ordem de avaliação seja preservada.

3. A ordem do for

for (int i = 1; i <= 5; i++) {
    System.out.println("Contagem: " + i);
}

A inicialização acontece uma vez. Antes de cada repetição, a condição é avaliada. Se for verdadeira, o corpo executa; depois acontece a atualização. O ciclo então volta à condição. No exemplo, os valores impressos vão de 1 a 5. Depois do corpo com 5, o incremento produz 6 e a condição deixa de ser verdadeira. O valor 6 não é impresso.

Começar em zero e usar i < 5 também produz cinco iterações, mas imprime de 0 a 4. Esse padrão será útil em arrays. Não confunda a quantidade de repetições com o valor final da variável. A variável declarada no cabeçalho fica no escopo do laço; para consultá-la depois, precisaria ser declarada fora, se essa consulta fizer parte da necessidade do programa.

4. Tabuada com limite claro

int numero = 7;
for (int i = 1; i <= 10; i++) {
    int produto = numero * i;
    System.out.printf("%d x %d = %d%n", numero, i, produto);
}

A variável numero permanece igual em todas as repetições. O contador muda de 1 a 10 e o produto é recalculado. Antes de executar, confira a primeira e a última linha: 7 x 1 = 7 e 7 x 10 = 70. Se o código usa i < 10, a última multiplicação desaparece. Se usa i = 0, uma linha com multiplicação por zero será incluída.

Para uma soma de produtos, declare o acumulador antes do laço. Criá-lo novamente dentro do corpo reinicia seu valor a cada passagem. Esse erro produz um número plausível em alguns casos e precisa ser investigado pelo fluxo das atribuições. Uma tabela com as colunas contador, produto e acumulador permite verificar as primeiras repetições manualmente.

5. While e atualização do estado

int contador = 0;
while (contador < 3) {
    System.out.println(contador);
    contador++;
}

O while verifica a condição antes do corpo. Se contador começasse em 3, nenhuma linha seria impressa. Com zero, imprime 0, 1 e 2. O incremento é necessário para a condição mudar nesse exemplo. Retirá-lo mantém o mesmo estado e causa repetição sem término. Uma condição inicial falsa e uma condição que nunca se torna falsa são casos diferentes.

No exercício da apostila com iteracao < 5 e início em zero, os valores são 0 a 4, não 0 a 5 como diz um trecho explicativo. O limite excluído deve ser respeitado ao contar. Essa mesma conferência evita acessar um array na posição igual ao seu comprimento.

6. Do/while, sentinela e menus

int tentativa = 5;
do {
    System.out.println("Executou ao menos uma vez");
    tentativa++;
} while (tentativa < 3);

O corpo executa uma vez apesar de a condição final ser falsa. Observe o ponto e vírgula depois da condição. Essa forma serve para uma operação que deve acontecer antes de decidir pela repetição, como apresentar um menu. A regra de entrada ainda precisa tratar dados ausentes ou inválidos.

Uma sentinela é um valor reservado para encerrar a leitura. Por exemplo, um menu pode usar 0 para sair. O valor não deve ser processado como uma operação comum depois que o programa o reconhece. No Playground, os dados são fornecidos previamente. Inclua a opção de saída na entrada de um menu: se o programa pedir outro dado após a última linha, receberá fim de entrada.

java.util.Scanner entrada = new java.util.Scanner(System.in);
int opcao;
do {
    System.out.println("1: consultar | 0: sair");
    if (!entrada.hasNextInt()) {
        System.out.println("Entrada ausente ou inválida");
        break;
    }
    opcao = entrada.nextInt();
    if (opcao == 1) {
        System.out.println("Consulta realizada");
    } else if (opcao != 0) {
        System.out.println("Opção desconhecida");
    }
} while (opcao != 0);

7. Break e continue

break encerra a estrutura de repetição ou switch mais próxima. Em um switch dentro de um while, um break do switch não encerra automaticamente o while. Para sair do menu, altere a variável que controla o laço ou faça o método informar que a repetição terminou. No projeto Combo, o retorno booleano da operação participa dessa decisão no método principal.

continue pula o restante do corpo da iteração atual. Em um for, a atualização do cabeçalho ainda acontece antes da próxima verificação. Em um while, um continue colocado antes do incremento pode impedir que a variável mude. Use essas instruções com atenção à atualização necessária em cada caminho.

int soma = 0;
for (int i = 1; i <= 5; i++) {
    if (i == 3) {
        continue;
    }
    soma += i;
}
System.out.println(soma); // 12: soma 1, 2, 4 e 5

8. Calcular a média da turma

Considere uma turma com 30 alunos e duas notas por aluno. Comece testando dois alunos e aumente a quantidade depois de conferir o resultado. Inicialize a soma das médias em zero, leia os dados de cada aluno, calcule sua média e acrescente esse resultado à soma. Depois do laço, divida pela quantidade de alunos. Com médias individuais 6 e 8, a média da turma deve ser 7.

Se a quantidade pode ser zero, a divisão precisa de validação. Também defina se notas inválidas serão rejeitadas, solicitarão nova leitura ou serão consideradas erro de entrada. Ao ler nome depois de nota numérica com Scanner, coordene nextLine conforme o capítulo anterior. A contagem precisa corresponder ao número de alunos efetivamente aceitos, especialmente se entradas forem descartadas.

9. Prática com laços aninhados e rastreamento

Um laço dentro de outro permite percorrer linhas e colunas. Para cada passagem do laço externo, o interno executa suas próprias repetições. Com duas linhas e três colunas, o corpo interno executa seis vezes. Use nomes como linha e coluna quando forem mais claros do que letras. Conte o trabalho antes de ampliar limites, para evitar executar milhares de repetições sem necessidade.

Para investigar um laço, imprima temporariamente os valores que controlam a condição e o acumulador. Depois de corrigir o problema, preserve apenas mensagens que façam parte do programa. No Playground, há botão para interromper e reiniciar o ambiente, e o tempo de execução é limitado. Uma interrupção por tempo não comprova que o algoritmo seja infinito: ele também pode estar demorando ou carregando recursos.

Praticar tabuada, comparar laços e executar um menu com saída. Explique por que a condição muda em cada atividade e o que aconteceria se a atualização fosse removida.

10. Teste de mesa: acompanhe antes e depois de cada corpo

Use uma tabela com contador, condição, valor processado e acumulador. Faça a primeira linha antes de executar o corpo. Depois registre a atualização e só então avalie a condição seguinte. Esse detalhe evita atribuir ao código uma ordem intuitiva que ele não segue. No for, a atualização ocorre depois do corpo; no while, você precisa escrevê-la no lugar adequado.

A soma é inicializada fora do corpo porque precisa sobreviver entre passagens. Se você declarar soma igual a zero novamente a cada iteração, não estará acumulando o histórico: só terá o valor da passagem atual. Esse é um exemplo de erro de lógica que o compilador não precisa rejeitar.

Use o rastreamento como ferramenta temporária. Em uma atividade com saída exata, impressões extras de depuração mudam o resultado. Retire-as depois de entender a falha ou escreva testes separados para conferir o estado. Não transforme um relatório de diagnóstico em parte acidental do contrato público do programa.

11. Invariantes e o motivo para acreditar no acumulador

Uma invariante é uma afirmação que você consegue manter verdadeira ao longo do laço. Na soma dos primeiros elementos de um array, antes de processar a posição i, o acumulador representa a soma das posições anteriores. No início, não há posição anterior e o acumulador zero está correto. Depois de somar o elemento i, a afirmação passa a valer para a próxima posição.

Essa forma de raciocinar serve para verificar um algoritmo sem testar todos os dados possíveis. Você confere o estado inicial, a preservação em uma passagem e o significado quando a condição termina. Um erro na inicialização ou no índice pode quebrar a afirmação imediatamente. Uma condição de término errada pode fazer a invariante valer para uma quantidade diferente da desejada.

Não é necessário escrever uma prova formal em cada exercício. Uma frase precisa já ajuda: “quantidade é o número de valores positivos aceitos”, por exemplo. Se você incrementa quantidade também quando ignora um negativo, a frase deixa de ser verdadeira. Esse contraste transforma uma revisão abstrata em uma pergunta direta sobre cada atribuição.

12. Limite inclusivo, limite exclusivo e contagens sem surpresa

O intervalo de 0 até n excluído contém n posições quando n não é negativo. Esse padrão combina com arrays, cujo último índice é length menos um. Já uma tabuada apresentada de 1 a 10 costuma usar os dois extremos incluídos. Escolha a convenção que acompanha o dado e escreva a primeira e a última passagem esperadas antes de executar.

Para n igual a zero, um laço iniciado em zero com condição i menor que n não executa o corpo. Para n igual a um, executa apenas na posição zero. Esses dois testes pequenos revelam mais sobre o limite do que uma execução com mil itens. Evite acrescentar ou retirar um do limite apenas para fazer uma saída específica coincidir; retorne à definição do intervalo.

O tipo do contador também importa. Incrementar um int além de seu máximo faz overflow. Um laço que espera ultrapassar Integer.MAX_VALUE pode voltar ao mínimo e nunca terminar da forma prevista. Nos exercícios, use limites pequenos e documentados. Em um método que recebe um limite externo, valide a faixa e pense no custo antes de prometer aceitar qualquer inteiro.

13. Escolher entre for, while e do/while pelo contrato

For agrupa inicialização, condição e atualização quando há uma progressão clara. While destaca uma condição de permanência, como ainda existir entrada. Do/while estabelece que o corpo acontece antes da primeira decisão de repetir. Não escolha do/while apenas por ser mais curto quando zero execuções é uma possibilidade legítima.

Mude o estado inicial para 3 nos dois casos e preveja a diferença. O primeiro não imprime. O segundo imprime uma vez, pois o contrato dessa estrutura coloca a decisão depois do trabalho. Quando reescrever uma forma na outra, preserve esse comportamento ou diga explicitamente que a regra mudou.

Na leitura de dados, um while com hasNext evita tentar consumir uma informação inexistente. Ainda assim, você precisa decidir o que fazer com um token que existe mas tem formato errado. Presença e validade não são a mesma verificação. A próxima seção combina as duas sem deixar a leitura presa no mesmo token.

14. Consumir entradas inválidas para garantir progresso

HasNextInt verifica o próximo token sem retirá-lo da entrada. Se um laço encontrar “texto”, imprimir um erro e voltar a hasNextInt, continuará vendo “texto” para sempre. O caminho de recusa também precisa avançar: consuma o token inválido com next ou encerre o processamento, conforme o contrato.

Em cada caminho, o programa consome algo, encontra a sentinela ou chega ao fim. Isso é uma justificativa de progresso. A sentinela zero não é contada como um valor aceito. Se o problema permitir zero como dado comum, você precisará de outra estratégia de término, como uma quantidade informada antes ou um comando separado.

O limite de execução do Playground serve para recuperar a interface de uma falha; ele não corrige o algoritmo. Use Interromper ao experimentar um laço deliberadamente sem término e restaure a atualização antes de continuar. Não dependa do limite de tempo como regra normal de saída.

15. Média por sentinela: calcule depois de saber a quantidade

O contrato deste laboratório aceita inteiros positivos, ignora negativos e termina com zero ou fim de entrada. Um token não inteiro é informado e descartado. A média só existe quando houve ao menos um positivo aceito. O exemplo usa long para a soma e detecta overflow, porque aumentar o tipo não o torna ilimitado.

A conversão para double aparece antes da divisão, evitando a perda da fração por aritmética inteira. A formatação de duas casas é uma escolha de apresentação. A quantidade conta apenas valores incorporados à soma, por isso o denominador representa o mesmo conjunto do numerador.

Teste entrada vazia, somente zero, somente negativos e um positivo seguido de fim de entrada. Nos três primeiros casos não há média. No último há média de um elemento mesmo sem sentinela, porque o contrato aceita fim de entrada. Não anuncie erro apenas por não haver zero se você decidiu que o fim também encerra legitimamente o processamento.

16. Break, continue e return têm alcances diferentes

Break encerra a repetição ou switch mais próximo ao qual se aplica. Continue avança para a próxima iteração do laço. Return sai do método. Quando um switch está dentro de um while, o break que encerra o switch não é uma instrução universal para sair do menu. Dê um significado à variável de continuidade e atualize-a no ramo de saída.

Em um for, continue ainda passa pela atualização do cabeçalho antes de reavaliar a condição. Em um while, não existe essa atualização implícita; se ela estiver depois do continue, poderá nunca acontecer. Para cada caminho, pergunte qual variável muda e se a próxima leitura consome outro dado.

Java permite rótulos para certas saídas de estruturas aninhadas, mas não use esse recurso como substituto de entender o fluxo. Em exercícios pequenos, um método separado com retorno claro frequentemente expressa melhor a busca que precisa terminar. Escolha o mecanismo pelo alcance realmente necessário e cubra o caminho de saída em um teste.

17. Laços aninhados e custo: conte o trabalho antes de ampliar

Se o laço externo executa m vezes e o interno n vezes para cada passagem, o corpo interno executa m vezes n, quando os limites são independentes. Uma grade de duas linhas e três colunas tem seis posições. Duplicar ambos os limites quadruplica essa quantidade. Esse raciocínio ajuda a reconhecer por que um algoritmo aparentemente pequeno pode ficar caro.

Nem todo laço aninhado custa exatamente o produto de dois números fixos. Se o limite interno depende da linha, some as quantidades de cada passagem. Um triângulo que processa 1, depois 2, depois 3 elementos tem seis visitas em três linhas, e não nove. A estrutura visual sozinha não prova a complexidade.

Evite fazer uma consulta lenta ou uma gravação externa em cada passagem sem perceber quantas vezes ela será chamada. Os primeiros exercícios trabalham em memória, mas a mesma contagem se torna importante em arquivos, banco de dados e interfaces. Primeiro corrija o algoritmo; depois meça uma carga representativa para decidir se uma otimização é necessária.

18. Investigar primos sem multiplicação que pode estourar

Um inteiro maior que um é primo quando não possui divisores positivos além de um e dele próprio. Ao encontrar um divisor, a busca pode terminar. Basta investigar até a raiz quadrada porque um divisor maior teria um par menor. Para evitar calcular divisor vezes divisor em int, o limite pode ser escrito como divisor menor ou igual a numero dividido por divisor.

O número 2 não exige nenhuma divisão no corpo, pois a condição inicial já é falsa; ele continua sendo reconhecido como primo. O número 49 precisa testar o divisor 7, exatamente na fronteira. Trocar menor ou igual por menor excluiria esse caso e poderia classificá-lo incorretamente.

O método expressa uma regra didática simples, não uma ferramenta criptográfica. Sua utilidade neste capítulo é relacionar condição, término e um teste que detecta um defeito na fronteira. Reescreva a explicação com suas palavras antes de tentar acelerar o algoritmo.

19. Depuração de laços: encontre a primeira passagem incorreta

Se a saída está errada, identifique o primeiro ponto em que o estado diverge da previsão. Uma média final incorreta pode vir de soma reiniciada, contador incrementado no caminho errado, divisão inteira ou último elemento ignorado. Acrescentar um valor ao resultado para compensar o teste atual não corrige nenhuma dessas causas.

Use breakpoints e observe condição, contador e acumulador. Se o programa não termina, verifique se todos os caminhos avançam. Um ramo pode funcionar e outro continuar lendo o mesmo dado. Se a operação apenas demora, conte o número esperado de passagens e distinga tempo de carga do runtime de tempo do seu próprio algoritmo.

Nos exemplos, mantenha o resultado do processamento separado do registro de depuração. Uma rotina que imprime cada passo pode parecer lenta por causa da saída, não da aritmética. Testes de desempenho exigem outra estratégia; para os fundamentos, escolha entradas pequenas e torne o estado legível.

20. Prática guiada, soluções e teste dos casos de borda

  1. Contagem: escreva um for que imprima 0, 1 e 2 em linhas separadas. Depois reescreva com while sem mudar a saída. Faça uma tabela com valor antes do corpo e valor depois da atualização.
  2. Tabuada: use o número 9 e multiplicadores de 1 a 10, inclusive. Imprima apenas as multiplicações em que o multiplicador é par. A saída deve conter cinco linhas, começando em 9 x 2 = 18 e terminando em 9 x 10 = 90.
  3. Média: implemente o laboratório por sentinela com o editor vazio. Use 10, -3, 20 e 0 como entrada. Depois teste somente 0 e confira a mensagem de ausência de positivos, sem dividir.
  4. Primalidade: preveja os resultados de 1, 2, 29 e 49 antes de executar. Explique por que o divisor 7 precisa participar do teste de 49.
Possível solução: tabuada com multiplicadores pares

A atualização de dois em dois visita diretamente os multiplicadores desejados. Outra solução válida percorre todos e usa uma condição de paridade. Compare as duas pela clareza do contrato, sem afirmar que uma diferença pequena decide o desempenho de qualquer aplicação.

Conferir contagem, ausência de dados e término

As duas contagens devem executar três vezes. Na versão while, inicialize o contador antes do laço e incremente depois da impressão. Na média, zero encerra sem entrar na soma. Se ele é o primeiro token, não há quantidade aceita e a saída é Sem valores positivos. No teste de primos, 1 é falso, 2 e 29 são verdadeiros e 49 é falso.

Você está pronto para avançar quando consegue explicar por que cada laço termina, quantos elementos foram processados e o que acontece sem elementos. O próximo tema guarda vários valores em estruturas; os limites e acumuladores estudados aqui serão usados em seus percursos.
