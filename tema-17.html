1. Passar da janela ao grafo de cena

JavaFX oferece uma biblioteca de interface com controles, layouts, propriedades observáveis e suporte a estilos. Uma aplicação estende Application e implementa start. O Stage representa uma janela; a Scene contém o grafo de objetos visuais. Os nós desse grafo incluem controles e contêineres. A biblioteca é obtida separadamente do JDK usado pelo laboratório.

O projeto deste capítulo utiliza JavaFX 21.0.10 com JDK 17 e Maven. A versão foi fixada para reproduzir o exercício; ao trocar a biblioteca, confira o JDK exigido pela versão escolhida. O Maven resolve também componentes específicos da plataforma. Um projeto que abre no Windows ainda precisa ser empacotado e conferido para Linux ou macOS.

Você vai reconstruir o formulário de notas com a mesma regra do laboratório Swing. Compare a organização das interfaces sem misturar os controles dos dois kits. O JavaFX trabalha com sua própria thread de aplicação, seu modelo de propriedades e seus layouts. O guia de instalação do OpenJFX explica as alternativas de build e resolução.

2. O ciclo de vida de Application

O lançamento cria a aplicação e prepara o ambiente gráfico. start recebe o Stage principal e é chamado na JavaFX Application Thread. Monte a cena e mostre a janela nesse método. O método init serve à inicialização que antecede start e não deve manipular controles que exigem a thread gráfica. stop permite encerrar recursos da aplicação quando ela termina.

Um recurso de fundo iniciado pela tela precisa de uma política de encerramento. Fechar a janela enquanto um executor próprio continua ativo pode manter o processo vivo ou deixar uma operação sem indicação de resultado. Para o laboratório de notas, não há executor nem conexão. Quando você acrescentar esses recursos, documente quem os cria, quem pode usá-los e quem os fecha.

Application.launch coordena esse ciclo e só deve ser utilizado conforme o contrato da biblioteca. Evite chamar start manualmente para contornar uma configuração incorreta. Se uma dependência gráfica estiver ausente, investigue o build, a plataforma selecionada e o comando de execução. Consulte os métodos de Application para distinguir as etapas.

3. Layout com GridPane e VBox

O formulário usa GridPane para associar rótulo e campo em colunas. Os espaçamentos horizontal e vertical definem intervalos entre células. A prioridade de crescimento do campo permite que ele aproveite espaço adicional. Um VBox organiza o formulário e a mensagem de resultado numa coluna. Insets define margens internas sem introduzir um componente vazio apenas para ocupar espaço.

Os controles calculam tamanhos preferidos e o layout redistribui o espaço. Isso ajuda quando a fonte muda, mas ainda exige testar textos compridos. O Label de resultado usa wrapText para permitir quebra de linha. Um formulário com conteúdo maior que a janela pode precisar de ScrollPane. Defina tamanhos mínimos com cuidado para não impedir o uso em uma tela menor.

O trecho abaixo pertence ao método start do App completo disponível no ZIP. Os controles são criados antes da composição. GridPane e VBox são classes de javafx.scene.layout; Insets pertence a javafx.geometry. A divisão entre criação, ligação de eventos e composição ajuda a localizar alterações sem concentrar toda a regra numa linha de montagem.

GridPane formulario = new GridPane();
formulario.setHgap(12);
formulario.setVgap(12);
formulario.add(rotulo, 0, 0);
formulario.add(nota, 1, 0);
formulario.add(conferir, 1, 1);
GridPane.setHgrow(nota, Priority.ALWAYS);
VBox raiz = new VBox(16, formulario, resultado);
raiz.setPadding(new Insets(24));
palco.setScene(new Scene(raiz, 480, 210));
palco.show();

4. Propriedades observáveis e binding

Uma propriedade observável permite acompanhar alterações de um valor. O texto de TextField possui uma textProperty; a disponibilidade de Button possui disableProperty. O laboratório vincula o estado desabilitado à condição de campo vazio. Assim, a interface acompanha a mudança do texto sem escrever um listener apenas para alternar o botão.

Um binding expressa uma dependência entre valores. Ele não elimina a necessidade de validar o conteúdo quando a ação ocorre. Um campo com espaços deixa de ser vazio para essa expressão, e o domínio ainda deve recusá-lo. A condição visual orienta a interação, enquanto a validação mantém o contrato completo. Não apresente o botão habilitado como garantia de que todos os campos estão corretos.

Bindings unidirecionais e bidirecionais têm usos diferentes. No primeiro caso, uma propriedade deriva de outra expressão; no segundo, alterações podem propagar nos dois sentidos. Ao conectar dois campos com conversão numérica, pense no estado temporário da digitação: um sinal de menos ou uma vírgula ainda pode fazer parte de uma edição incompleta. Evite converter cada tecla em uma gravação definitiva.

conferir.disableProperty().bind(nota.textProperty().isEmpty());
conferir.setDefaultButton(true);
rotulo.setLabelFor(nota);

5. Eventos e atualização do estado apresentado

setOnAction recebe uma função que reage à ação do botão. O código lê a entrada, chama Nota.avaliar e atualiza o Label. A regra é a mesma da janela Swing, porém a apresentação usa objetos JavaFX. Essa reutilização demonstra a fronteira definida no tema 15: a decisão de negócio permanece fora da biblioteca visual.

Quando várias telas dependem de dados compartilhados, escolha uma fonte de estado e descreva como cada tela recebe atualizações. Copiar a mesma informação para campos e listas sem uma política pode produzir valores divergentes. Para uma tabela, use um modelo de linha e uma coleção observável adequada. A atualização de um item precisa refletir o contrato do controle e das propriedades que ele observa.

Um listener que foi registrado num objeto de vida longa pode manter referências a uma tela que já deveria ter sido descartada. Ao criar telas repetidamente, acompanhe quem registra e remove listeners e tarefas. Esse problema costuma aparecer como crescimento de memória ou atualizações em componentes antigos. A relação de observação também faz parte do ciclo de vida da interface.

6. FXML, controlador e CSS

FXML descreve uma árvore de objetos em um documento XML. O FXMLLoader cria os objetos e pode relacioná-los a um controlador. O atributo fx:id identifica um objeto para injeção no controlador; ele precisa corresponder ao campo ou mecanismo configurado. FXML separa a descrição da cena do código de eventos, mas a regra do domínio ainda deve ficar numa classe testável.

Em um projeto modular, o pacote do controlador pode precisar ser aberto ao módulo javafx.fxml para a injeção por reflexão. O arquivo FXML e o CSS devem estar no caminho de recursos usado na distribuição. Um caminho que funciona apontando para a pasta src pode falhar depois do empacotamento. Carregue recursos pelo classpath e trate a ausência como erro de configuração.

O laboratório começa com montagem em Java para que você acompanhe todos os objetos. Como evolução, mova apenas a estrutura visual para FXML e acrescente a dependência javafx-fxml da mesma versão. O guia oficial de FXML apresenta carregamento e controladores. CSS pode padronizar cores e estados; mantenha contraste e foco visíveis em cada estado.

7. Build, execução e diagnóstico

Abra o pom.xml do pacote na IDE ou use o terminal na pasta extraída. mvn clean compile resolve as dependências e compila. O teste simples usa apenas as classes de domínio em target/classes. mvn javafx:run chama o plugin configurado para a classe br.estudo.App. A primeira execução precisa de internet para obter bibliotecas que ainda não estejam no cache.

mvn clean compile
java -cp target/classes br.estudo.Testes
mvn javafx:run

8. Prática: comparar duas interfaces da mesma regra

Execute o teste de domínio e obtenha as doze verificações. Abra a interface JavaFX e repita as entradas utilizadas em Swing. Compare os resultados e registre diferenças de apresentação. A mesma nota deve produzir a mesma decisão nas duas aplicações. Teste também espaços e NaN para comprovar que o estado do botão não substitui a validação.

Acrescente um campo de nome e apresente uma mensagem completa sem alterar a classe de regra de notas. Depois defina um estilo para o resultado e confirme que a informação permanece compreensível sem depender da cor. A atividade termina com navegação por teclado, redimensionamento legível e instruções de execução suficientes para outra pessoa abrir a janela.

Posso atualizar um Label numa thread de consulta?

Faça a consulta fora da thread gráfica e encaminhe a atualização por Platform.runLater ou pelos eventos de Task/Service apropriados. O controle continua sujeito às regras da JavaFX Application Thread.
