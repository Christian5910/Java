1. Aprender programando: seu primeiro roteiro de estudo

Você não precisa conhecer outra linguagem para começar. Precisa conseguir criar e salvar um arquivo, localizar uma pasta e abrir um terminal. Um terminal recebe comandos; um editor altera o texto do programa; o compilador verifica esse texto. São tarefas diferentes. Se ainda não conhece o terminal, use primeiro o Playground e depois repita o mesmo exemplo no computador. Compare os dois resultados: mudar de ferramenta não muda a soma feita pelo programa.

Estude em três passagens. Na primeira, execute o exemplo sem modificações. Na segunda, preveja o resultado de uma alteração pequena e confira. Na terceira, feche o exemplo e escreva uma solução a partir do enunciado. Copiar ajuda a conhecer a forma; reconstruir e explicar mostra se você compreendeu. Ao encontrar uma palavra nova, volte à seção correspondente em vez de tentar decorar toda a plataforma de uma vez.

  • Ao terminar este tema: criar, compilar e executar uma aplicação de console; explicar JDK e JVM; investigar uma falha simples; organizar duas classes e reproduzir sua execução.
  • Pré-requisito para o tema 2: reconhecer o método principal e a ordem das instruções. Os detalhes de objetos serão retomados nos temas 7 a 10.
  • Registro de estudo: guarde o enunciado, a saída que previu, o código e uma explicação do erro que corrigiu. Isso é mais útil do que guardar apenas uma captura de tela.

2. Para que serve estudar Java

Java é uma linguagem de programação de propósito geral. Com ela, você descreve dados e operações, define regras de decisão e organiza comportamentos em classes. Um programa de console pode calcular uma média ou consultar uma conta; uma aplicação maior pode receber requisições, armazenar informações e aplicar regras de negócio. Os fundamentos continuam presentes nos dois casos. Antes de usar bibliotecas de uma aplicação maior, precisamos entender o que cada instrução faz e como os valores mudam durante a execução.

Java e JavaScript são linguagens diferentes. O código desta apostila usa classes, tipos e bibliotecas da plataforma Java. O site usa JavaScript para a navegação e para integrar o ambiente de execução ao navegador. Escrever System.out.println em um arquivo JavaScript não o transforma em Java. O Playground possui um compilador e uma máquina virtual próprios para executar os exemplos Java.

3. História e referências que envelheceram

A linguagem começou a ser desenvolvida na Sun Microsystems no início da década de 1990, com participação de James Gosling. O projeto passou pelo nome Oak antes de se tornar Java. Sua apresentação pública ocorreu em 1995; o JDK 1.0 foi lançado em janeiro de 1996, conforme o histórico dos tutoriais da Oracle. Em 2010, a Oracle concluiu a aquisição da Sun.

Applets eram pequenos programas Java executados com um plug-in de navegador. Esse mecanismo pertence à história da plataforma e não é necessário para estudar aqui. O Playground usa uma JVM em WebAssembly, carregada pelo navegador. Neste guia, Java 17 é a referência para a sintaxe; as bibliotecas disponíveis no editor são explicadas antes da execução. Recursos de versões posteriores precisam de um ambiente local compatível.

4. JDK, JVM, ambiente de execução e IDE

A JVM, máquina virtual Java, executa instruções de bytecode. O JDK reúne ferramentas de desenvolvimento, como o compilador javac, o comando java e a ferramenta de documentação javadoc, além dos componentes necessários à execução. JRE é o nome usado para o ambiente de execução. A forma de distribuir esse ambiente varia entre versões e fornecedores; instalar uma IDE não comprova que o JDK usado pelo projeto foi configurado corretamente.

Uma IDE, como NetBeans, IntelliJ IDEA ou Eclipse, oferece edição, navegação e depuração. O VS Code pode oferecer essas funções com extensões apropriadas. A IDE chama ferramentas Java e organiza projetos; ela não substitui as regras da linguagem. Se um exemplo não compila, confira a mensagem do compilador antes de atribuir o problema ao editor. O mesmo programa pode ser desenvolvido em editores diferentes.

5. Preparar uma pasta e trabalhar com segurança

Crie uma pasta de exercícios em um local onde você tenha permissão para gravar. Dentro dela, crie uma pasta por atividade, por exemplo java-estudos/primeiro-programa. Não coloque arquivos pessoais ou senhas nos exemplos. Evite trabalhar diretamente na pasta de instalação do Java: o JDK é uma ferramenta e seu projeto é outro conjunto de arquivos.

No Windows, habilite a exibição das extensões de arquivos no Explorador. Um arquivo apresentado como Main.java pode, na verdade, ser Main.java.txt se a extensão estiver oculta. Use um editor de texto ou de código e salve como UTF-8. Um processador de textos pode introduzir formatação e aspas tipográficas que o compilador não reconhece como delimitadores.

6. Instalar e conferir um JDK no computador

Para programar fora do navegador, escolha uma distribuição do JDK para seu sistema operacional e arquitetura. OpenJDK é um projeto de implementação da plataforma; distribuições como Eclipse Temurin e Oracle JDK fornecem pacotes instaláveis. Versão, atualizações e licença da distribuição são decisões distintas. Para acompanhar o guia, configure Java 17. A seção de instalação e ferramentas reúne os links de download. Uma versão posterior instalada na máquina não muda automaticamente a configuração do projeto.

Depois da instalação, abra um terminal novo e execute os dois comandos abaixo. O primeiro identifica o ambiente chamado para executar; o segundo identifica o compilador. Se apenas java funciona, confira se foi instalado um JDK completo e se seu diretório bin está no PATH. Quando há várias instalações, os comandos podem apontar para diretórios diferentes. Confira também a configuração do JDK dentro da IDE.

java -version
javac -version

JAVA_HOME, quando uma ferramenta o exige, deve apontar para a pasta do JDK, sem acrescentar bin. Já o PATH inclui a pasta de executáveis. No PowerShell, Get-Command java e Get-Command javac mostram os comandos resolvidos; $env:JAVA_HOME consulta a variável. No Linux e macOS, command -v java, command -v javac e echo "$JAVA_HOME" cumprem essa investigação. Evite copiar um caminho de outra máquina: o nome exato do diretório depende da instalação.

Use o primeiro programa deste tema como teste da instalação. Compile em UTF-8 e execute a classe a partir da mesma pasta. Alterar o texto e executar sem recompilar pode mostrar a versão antiga do .class. Se o resultado parecer ignorar sua edição, confira o arquivo salvo, o diretório atual e a etapa de compilação antes de modificar o programa.

7. Do arquivo fonte ao resultado

Um arquivo Main.java contém texto que segue a sintaxe Java. O compilador analisa esse texto, verifica tipos e produz um ou mais arquivos .class. A JVM carrega essas classes e executa o programa. Implementações podem interpretar bytecode e compilar trechos durante a execução, usando JIT. Portanto, compilar o arquivo e executar a classe são etapas diferentes, mesmo quando o botão da IDE faz ambas.

A portabilidade depende de uma JVM compatível e dos recursos usados. Um arquivo compilado para uma versão mais nova pode não executar em uma JVM antiga. Caminhos de arquivo, bibliotecas nativas e dependências externas também interferem. Definir uma versão de referência e evitar caminhos específicos do computador facilita executar o mesmo exercício em computadores diferentes.

8. Seu primeiro programa completo

public class Main {
    public static void main(String[] args) {
        System.out.println("Olá, Java!");
        System.out.println(5 + 10);
    }
}

Salve esse texto como Main.java. public class Main declara a classe pública. As chaves delimitam a classe e o corpo do método. O método public static void main(String[] args) é o ponto de entrada usado nesta apostila. static permite chamá-lo sem criar um objeto de Main; void indica ausência de valor de retorno; args recebe argumentos de linha de comando. O nome desse parâmetro pode mudar, mas manter args facilita reconhecer a convenção.

A primeira instrução imprime um texto e termina a linha. A segunda calcula a soma e imprime 15. As aspas duplas delimitam o texto e não aparecem na saída. A instrução de chamada termina com ponto e vírgula; a declaração do método e os blocos não recebem um ponto e vírgula depois de cada chave. O nome do arquivo deve coincidir com a classe pública, inclusive nas maiúsculas.

9. Ler o primeiro programa, palavra por palavra

Pense na classe como uma unidade de organização do código. O bloco externo de Main contém métodos. Um método reúne instruções para uma tarefa. O método main desta versão é o ponto de entrada da aplicação de console. Quando a JVM o inicia, as instruções do seu corpo são executadas em ordem, exceto quando o fluxo é alterado por chamadas, decisões, repetições ou falhas.

public
Define uma forma de acesso. No método principal convencional, permite que o inicializador o encontre como ponto de entrada público.
class Main
Declara o tipo chamado Main. O nome tem maiúscula por convenção e precisa coincidir com Main.java quando a classe pública é compilada com javac.
static
Associa o método à classe; para iniciá-lo, não precisamos escrever new Main().
void
O método não devolve um valor ao chamador. Isso não impede imprimir informações.
String[] args
É o parâmetro que recebe um array de textos da linha de comando. Ele pode conter zero elementos.
System.out.println(...)
Chama a operação de impressão do fluxo de saída padrão. O argumento dentro dos parênteses é a informação a imprimir.

java.lang é importado implicitamente; por isso, os exemplos usam String e System sem um import explícito. Isso não significa que todas as classes da biblioteca padrão estejam disponíveis por nome curto. Para Scanner, por exemplo, precisamos de import ou do nome qualificado.

Indentação não muda o significado do bloco, mas permite enxergar sua estrutura. Use uma instrução por linha, quatro espaços por nível e nomes legíveis. O ponto e vírgula encerra muitas instruções; ele não deve ser colocado mecanicamente após toda linha. Comentários // terminam no fim da linha, enquanto /* ... */ pode ocupar várias linhas. Comentários de bloco não se aninham.

10. Compilar e executar no computador

javac -encoding UTF-8 Main.java
java Main

Execute os comandos no diretório do arquivo. O primeiro compila; o segundo informa o nome da classe, sem .java ou .class. Se a instalação não reconhecer javac, verifique o JDK e a variável PATH. Se a IDE e o terminal usam versões diferentes, o comportamento do projeto pode divergir. Para os exemplos desta apostila, use um JDK compatível com Java 17; recursos de versões posteriores precisam de estudo e configuração próprios.

No Playground, o arquivo principal também se chama Main.java. É possível colocar classes auxiliares sem public no mesmo arquivo. Projetos com pacotes, vários arquivos e dependências são discutidos no estudo, mas os exercícios do editor usam um único arquivo e a biblioteca padrão disponível no ambiente. Baixe o código para continuar na sua IDE quando o projeto crescer.

11. Um laboratório de saída, escapes e argumentos

Execute primeiro sem argumentos: java Main. Depois execute java Main Ana. As últimas linhas passam a ser Argumentos: 1 e Primeiro: Ana. Para passar um texto com espaços como um único argumento, use java Main "Ana Silva". Digitar Ana depois que o programa começou não altera o array: argumentos são recebidos no início. Ler enquanto o programa executa é outra operação, estudada com Scanner no tema 2.

A condição args.length > 0 protege o acesso à primeira posição. Você ainda não precisa dominar arrays: basta reconhecer que tentar ler uma posição ausente produz uma falha. A barra invertida de introduz uma sequência de escape dentro do literal, enquanto \ representa uma barra no texto. Uma barra em uma mensagem não cria uma pasta no computador.

12. Compilação reproduzível e compatibilidade

Separe os arquivos produzidos em uma pasta chamada out. O comando abaixo pede ao compilador de um JDK 17 ou posterior que use a linguagem e a API públicas da versão 17 e gere classes para esse destino. Ele não instala dependências, não converte bibliotecas externas para Java 17 e não garante compatibilidade com recursos nativos de qualquer sistema.

javac --release 17 -encoding UTF-8 -d out Main.java
java -cp out Main

-d out define o diretório de saída e -cp out informa onde o inicializador deve procurar classes. Não escreva java out/Main.class: no modo de execução de classes, o argumento é um nome de classe. --release 17 pode não existir em um compilador antigo demais. Confira javac -version antes de usar as opções.

Também é possível executar um fonte simples com java Main.java em JDKs compatíveis com esse modo. Nesse caso, o inicializador compila o fonte para execução; isso difere de usar java Main sobre uma classe já compilada. Para entender e diagnosticar o processo, pratique primeiro as duas etapas explícitas. As opções estão nos manuais oficiais de javac e java.

Uma máquina que tem um JDK mais recente pode compilar para 17, mas uma biblioteca que você adicionou pode exigir uma versão maior. Compatibilidade envolve fonte, bytecode, APIs e dependências. Registre a versão usada no projeto e confira a configuração do compilador na IDE. Para esta trilha, usar 17 é uma decisão didática estável; não é uma afirmação de que seja a versão mais recente.

13. Pacotes, importações e dois arquivos de verdade

Quando o projeto cresce, um pacote organiza nomes. package estudo; define que o nome completo da classe é estudo.Main. Uma pasta compatível com esse nome ajuda ferramentas e pessoas a localizá-la. Um import permite escrever um nome curto de outro pacote, mas não copia código, não executa uma classe e não instala uma biblioteca.

projeto/
  src/
    estudo/
      Main.java
      Mensagens.java
  out/

Salve os dois arquivos seguintes nos caminhos mostrados. É um laboratório para JDK local: o Playground usa um único Main.java sem pacote.

javac --release 17 -encoding UTF-8 -d out src/estudo/Main.java src/estudo/Mensagens.java
java -cp out estudo.Main

A saída é Olá, Ana!. As classes estão no mesmo pacote, então não precisamos importar Mensagens em Main. No segundo arquivo, return devolve um texto; em Main, esse retorno é entregue a println. O fluxo vai de main para boasVindas e volta com o resultado. Métodos, parâmetros e acesso serão aprofundados nos temas 7 a 10.

No classpath, forneça a pasta que contém estudo, isto é, out, e não out/estudo. Para listar várias entradas de classpath, o separador é ; no Windows e : no Linux/macOS. Em PowerShell, coloque uma lista com ponto e vírgula entre aspas para que o terminal a passe como um único argumento.

14. Distribuir um JAR e executá-lo em outra pasta

Um arquivo JAR reúne classes e recursos. Para o projeto de duas classes acima, execute na pasta projeto:

jar --create --file estudo.jar --main-class estudo.Main -C out .
java -jar estudo.jar

--main-class registra o ponto de entrada no manifesto. -C out . inclui o conteúdo do diretório out com seus caminhos relativos. A saída deve continuar sendo Olá, Ana!. Copie o JAR para uma pasta vazia e execute-o de lá: isso ajuda a perceber dependências acidentais de arquivos que só existiam na pasta do projeto.

Esse JAR não inclui uma instalação completa de Java nem empacota automaticamente bibliotecas externas. Quem o executa precisa de um runtime compatível e dos recursos exigidos pelo programa. Ferramentas como jlink e jpackage atendem outras necessidades de distribuição, estudadas no tema 19. Não acrescente essas ferramentas ao primeiro exercício antes de saber explicar o que o JAR contém. Consulte o manual de jar ao alterar o empacotamento.

15. Carregamento, memória e coleta de lixo

Ao executar um programa, a JVM carrega definições de classes conforme necessário e prepara as estruturas usadas pelos métodos. O caminho de classes ajuda a localizar código; uma importação no fonte apenas resolve nomes e não baixa bibliotecas. Cada chamada de método usa um quadro de execução com seus dados locais. Instâncias e arrays pertencem ao heap no modelo da JVM. Para entender o compartilhamento de objetos, desenhe variáveis e referências, sem supor que cada atribuição cria uma cópia.

O coletor de lixo pode recuperar memória de objetos que deixaram de ser alcançáveis. Atribuir null a uma variável não apaga o objeto imediatamente, e outra referência pode mantê-lo acessível. Também pode haver retenção indesejada de objetos em listas que nunca são limpas. Arquivos e conexões exigem fechamento próprio; recuperar memória não substitui esse cuidado. A especificação da JVM distingue o modelo de execução das escolhas de implementação.

HotSpot, uma implementação da JVM, pode usar compilação JIT para otimizar trechos durante a execução. Não existe um número universal de chamadas que garanta essa compilação nem uma promessa geral de desempenho em relação a outra linguagem. O comportamento depende da implementação, do programa e da carga. Da mesma forma, coletores como G1 e ZGC têm objetivos e custos diferentes; escolher um nome de coletor não garante uma latência específica. Para os primeiros exercícios, concentre-se em acompanhar referências, chamadas de métodos e o estado de cada objeto.

16. O que a JVM garante e o que depende do ambiente

Um modelo útil é: fonte → compilador → bytecode → carregamento → execução. A especificação define comportamentos observáveis; uma implementação pode otimizar a forma de produzi-los. Não use esse desenho como um mapa literal de endereços físicos. Uma otimização pode eliminar uma alocação sem mudar o resultado que o programa precisa apresentar.

Na perspectiva do programa, atribuir uma referência a outra variável não clona o objeto. Alterações por uma referência podem ser visíveis por outra. O coletor de lixo pode recuperar memória de objetos que deixaram de ser alcançáveis, enquanto o ciclo de vida de um arquivo ou conexão precisa de gerenciamento explícito. “Java tem GC” não significa que uma lista crescente sem limite seja segura.

O programa também interage com um sistema operacional: permissões, caminhos, fuso horário e codificação podem mudar o resultado. Prefira a API de caminhos a montar separadores manualmente e informe codificações ao ler e gravar arquivos. Esses assuntos aparecem com exemplos no tema 12. Para medir desempenho, use uma carga representativa e ferramentas apropriadas; uma execução curta do primeiro programa mistura inicialização com o trabalho que você queria medir.

17. Ferramentas que acompanham o desenvolvimento

Além de javac e java, o JDK oferece ferramentas para investigar e distribuir programas. javap -c Main permite observar instruções do bytecode compilado; javadoc gera documentação a partir de declarações e comentários apropriados; jar reúne classes e recursos em um arquivo de distribuição. Um JAR não se torna executável apenas por reunir arquivos: o modo de inicialização e as dependências precisam estar definidos.

jshell é um ambiente interativo do JDK para avaliar expressões e pequenas declarações. Ele ajuda a conferir uma divisão inteira ou um método de texto sem montar um projeto completo. Um resultado no JShell não prova que um arquivo com importações ausentes, escopo diferente ou outro ponto de entrada irá compilar. O Playground deste site trabalha com Main.java, não com uma sessão de JShell. Consulte as ferramentas do JDK no Dev.java para relacionar cada comando à sua tarefa.

18. Ler mensagens de erro

Um erro de compilação impede gerar ou executar a versão atual, por exemplo uma variável não declarada ou uma chave ausente. Um erro de execução acontece depois que o programa começa, como acessar uma posição inexistente de um array. Um erro de lógica produz um resultado incompatível com a regra, mesmo que não apareça mensagem de falha. Calcular média sem parênteses pode ser um erro de lógica; usar um nome inexistente pode ser erro de compilação.

Leia primeiro o arquivo, a linha e a descrição do erro inicial. Uma chave ausente pode provocar várias mensagens posteriores. Corrija a causa e compile novamente. Métodos chamados media ou main2 são métodos comuns: eles só participam da execução se forem chamados. O ponto de entrada dos programas deste guia é main.

19. Investigar erros com um procedimento que você pode repetir

Não troque várias linhas de uma vez para “ver se funciona”. Reproduza a falha, leia a primeira mensagem, proponha uma causa e mude apenas o necessário. Rode novamente com a mesma entrada. Se o erro mudou, volte a verificar sua hipótese. Guarde uma cópia funcionando antes de um experimento maior.

Uma stack trace apresenta o tipo da falha e os métodos percorridos até ela. Procure o primeiro quadro pertencente ao seu código, por exemplo at Main.main(Main.java:8). A linha 8 é onde a falha se manifestou, não necessariamente onde o dado incorreto surgiu. Acompanhe o valor até sua origem. Mensagens exatas variam conforme ferramenta, versão e idioma; aprenda a reconhecer a informação, não a decorar toda a frase.

Na IDE, coloque um breakpoint em uma instrução executável. Use “Step over” para executar uma linha sem entrar no método chamado e “Step into” para investigar uma chamada. Observe valores locais e a pilha de chamadas. Se não parar, confira se o programa foi iniciado em modo de depuração e se está executando a classe que você alterou. Retire impressões temporárias de diagnóstico quando terminar.

20. Do primeiro arquivo ao trabalho profissional: como seguir a trilha

Proficiência exige aplicar conceitos a problemas novos e manter software depois da primeira execução correta. Use esta trilha como percurso: fundamentos nos temas 1 a 6, modelagem e orientação a objetos nos temas 7 a 10, coleções, persistência, concorrência e testes nos temas 11 a 14. Depois escolha uma plataforma: desktop, Android ou backend. Você não precisa estudar todas ao mesmo tempo para praticar bem uma delas.

Em cada projeto, comece por uma regra pequena, escreva critérios de aceitação e registre o comportamento esperado para dados válidos, inválidos e limites. Acrescente controle de versão, documentação para execução e testes repetíveis. Os laboratórios do Extra ajudam nessa transição; baixar um projeto e rodá-lo é o início, explicar e modificar suas decisões é a prática seguinte.

Antes de avançar, seja capaz de explicar sem consultar: qual arquivo você edita; qual comando compila; qual nome a JVM executa; de onde vêm as classes; e como outra pessoa reproduziria o resultado. Saber a resposta para uma dúvida específica é útil. Saber investigá-la quando o ambiente muda é uma habilidade profissional.

21. Prática e revisão

Execute o primeiro programa, altere a mensagem e imprima seu nome em outra linha. Antes de executar, escreva qual saída espera. Em seguida, remova propositalmente um ponto e vírgula e observe a mensagem do compilador. Restaure o código e troque main por outro nome para distinguir compilação de inicialização. Ao revisar sua solução, mostre o arquivo fonte, o papel do compilador e o ponto em que a JVM começa.

Abrir a atividade de primeiro programa. Referências complementares: primeiros passos no Dev.java e contexto da descontinuação de applets.

22. Prática guiada, soluções e critérios para avançar

Faça os exercícios sem abrir a resposta. Compare a saída e explique por que ela ocorre. Os erros deliberados devem ser experimentados em uma cópia do programa; restaure o arquivo antes do próximo exercício.

  1. Apresentação: escreva Main.java para imprimir três linhas: seu nome fictício, “Estudando Java” e a soma de 12 com 8. A última linha deve ser 20, e não 128.
  2. Argumentos: adapte o laboratório de saída para informar “Sem nome” quando não houver argumentos e saudar o primeiro argumento quando houver. Teste sem argumento, com Ana e com “Ana Silva”.
  3. Diagnóstico: remova um ponto e vírgula, depois altere Main para main apenas no nome do arquivo. Registre se a falha acontece na compilação ou na inicialização e restaure cada alteração separadamente.
  4. Distribuição: reproduza o laboratório de duas classes, gere o JAR e execute-o em outra pasta. A saída precisa ser a mesma.
  5. Explique: por que modificar Main.java e chamar apenas java Main pode mostrar uma mensagem antiga?
Conferir solução: apresentação

Sem texto antes dos valores, + faz a soma numérica. Se usar “Soma: ”, coloque os parênteses ao redor da operação.

Conferir solução: argumentos e diagnóstico

Com java Main Ana, a saída é Olá, Ana!. Com o argumento entre aspas, Olá, Ana Silva!. O ponto e vírgula ausente impede compilar. No javac, um arquivo main.java com public class Main tem nome incompatível. Apenas executar uma classe antiga não recompila o fonte: é preciso compilar a alteração salva.

Autoavaliação comentada
Uma IDE e uma JVM são a mesma coisa?
Não. A IDE auxilia o desenvolvimento; a JVM executa bytecode.
Importar Scanner instala uma biblioteca?
Não. O import resolve o nome; Scanner já faz parte da biblioteca padrão.
É necessário um plug-in Java no navegador?
Não. O Playground integra seu próprio runtime, e o JDK local é outro ambiente.
O coletor de lixo fecha qualquer arquivo?
Não. Recursos externos exigem controle de ciclo de vida.
Compilar sem erros garante a regra correta?
Não. Uma fórmula incorreta pode compilar e executar normalmente; confira a saída esperada.

Você pode avançar quando: reproduzir um programa do zero, diferenciar compilação e execução, encontrar a causa de uma falha simples e explicar como repetir o resultado em outra pasta. Se ainda depender de copiar os comandos sem entender a pasta e a classe, refaça o laboratório. Continue com lógica, tipos e dados de entrada.
