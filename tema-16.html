16 · Interfaces gráficas com Swing

Monte uma interface Swing que valida a entrada e respeita a thread de eventos, sem perder a regra de negócio.

1. Criar a interface usando o próprio Java

Swing permite construir uma interface gráfica com classes Java da biblioteca de desktop. Uma janela JFrame contém componentes como rótulos, campos e botões. O programa reage a eventos produzidos pelo usuário e pelo sistema de janelas. Diferentemente do menu sequencial com Scanner, a aplicação mantém um ciclo de eventos e aguarda ações que podem acontecer em várias ordens.

Neste capítulo, você vai transformar a regra de notas numa janela simples. O usuário digita um valor, aciona Conferir e lê a situação. A regra continua numa classe sem dependência gráfica. O formulário trata a conversão e apresenta as mensagens, sem guardar a nota como uma variável global acessível a qualquer tela. Essa separação permite executar os testes de domínio mesmo em uma máquina sem monitor.

O laboratório requer JDK 17 ou compatível e um ambiente gráfico do sistema operacional. Não há dependência Maven. O módulo java.desktop fornece Swing e AWT. No Playground do site, use os programas de console dos fundamentos; uma janela nativa precisa ser executada localmente. O pacote abaixo inclui os fontes completos e instruções de terminal.

2. Janela, contêiner e componente

JFrame representa a janela de topo. JPanel agrupa controles e pode ser inserido no conteúdo da janela. JLabel apresenta texto, JTextField permite editar uma linha e JButton representa uma ação. O nome da variável deve ajudar a identificar o papel de cada controle. Um campo chamado nota é mais fácil de acompanhar do que campo1, especialmente quando a janela recebe novos elementos.

Um layout manager calcula posições e tamanhos conforme o espaço disponível e os tamanhos preferidos dos componentes. BorderLayout organiza regiões; FlowLayout distribui uma linha que pode se reorganizar; GridBagLayout oferece restrições mais detalhadas. Escolha um layout que corresponda ao formulário. O exemplo combina BorderLayout para a estrutura e FlowLayout para a linha de entrada.

Posições absolutas com setBounds exigem adivinhar dimensões que mudam com fonte, tradução, escala e aparência do sistema. Com um layout, pack calcula um tamanho inicial a partir dos componentes. Ainda é necessário verificar o redimensionamento e textos maiores. Um gerenciador de layout reduz trabalho manual; ele não garante sozinho que um formulário com dezenas de campos seja compreensível.

3. A thread que cuida dos eventos

A Event Dispatch Thread, ou EDT, processa eventos e atualizações da interface Swing. Crie e altere os componentes nessa thread. SwingUtilities.invokeLater agenda uma ação para esse fluxo. O método main pode preparar a inicialização e solicitar a abertura, deixando o ciclo de eventos assumir a interação. Consulte o guia oficial da EDT para as regras de acesso.

Uma ação demorada dentro do listener ocupa a EDT. Enquanto ela espera uma requisição ou percorre um arquivo grande, pintura, cliques e movimento da janela podem ficar sem resposta. Para o cálculo de uma nota, a operação é curta. Quando houver rede ou processamento demorado, use uma tarefa apropriada e devolva apenas o resultado para a interface. O tema 18 aprofunda essa coordenação.

Sincronizar um campo com synchronized não transforma qualquer thread numa thread autorizada a manipular Swing. O controle de concorrência do domínio e o acesso à interface são questões relacionadas, com regras diferentes. Mantenha o trabalho pesado fora da EDT e concentre as alterações visuais nela.

public static void main(String[] args) {
    javax.swing.SwingUtilities.invokeLater(Main::abrir);
}

4. Montar o formulário e estabelecer uma ação

O formulário do ZIP associa o JLabel ao campo com setLabelFor. O botão recebe um ActionListener. Quando a ação ocorre, o listener lê getText, chama Nota.avaliar e coloca o retorno no rótulo de resultado. Uma IllegalArgumentException esperada se transforma numa orientação de preenchimento, preservando o campo para correção.

O botão é definido como ação padrão da janela para que Enter execute a conferência. O mnemônico C permite acesso pelo atalho apresentado pelo sistema. O fechamento usa EXIT_ON_CLOSE porque o laboratório possui uma única janela e não mantém gravação pendente. Em um aplicativo com várias janelas ou edição não salva, o fechamento precisa de uma política que respeite o estado do trabalho.

O trecho abaixo pertence ao método abrir do Main fornecido. As variáveis nota, resultado e conferir são controles criados nesse mesmo método. A classe Nota está no mesmo pacote br.estudo e permanece independente de javax.swing.

conferir.addActionListener(evento -> {
    try {
        resultado.setText(Nota.avaliar(nota.getText()));
    } catch (IllegalArgumentException erro) {
        resultado.setText(erro.getMessage());
        nota.requestFocusInWindow();
    }
});
janela.getRootPane().setDefaultButton(conferir);

5. Validar um número antes de decidir a situação

Double.parseDouble aceita formatos que talvez não correspondam ao formulário desejado. No laboratório, a vírgula é convertida para ponto para permitir a entrada 7,5. A classe ainda precisa recusar NaN e infinitos, porque comparações de faixa sozinhas podem deixar passar NaN. Double.isFinite verifica essa condição antes de comparar com 0 e 10.

Essa normalização é adequada ao pequeno campo decimal descrito. Ela não implementa toda a formatação regional: uma entrada com separador de milhar e separador decimal exige uma estratégia de parsing com Locale e formato definido. Para valores financeiros, retome BigDecimal no tema 12. Escolha o tipo e o formato conforme o contrato da operação.

A validação visual pode apontar o campo com erro antes do envio, enquanto a classe de domínio mantém a regra final. Não use apenas cor para indicar a recusa. Uma mensagem como Use um número de 0 a 10 informa o que precisa ser corrigido. O resultado deve continuar legível até a próxima ação, permitindo que o usuário compare a entrada com a explicação.

6. Compilar, executar e conferir o comportamento

Extraia o pacote numa pasta própria. Os três arquivos ficam em src/br/estudo e declaram package br.estudo. Execute o compilador com UTF-8 e grave as classes em out. A execução utiliza o nome qualificado, sem caminho de arquivo e sem a extensão .class. O comando de testes não abre a interface.

javac --release 17 -encoding UTF-8 -d out src/br/estudo/Nota.java src/br/estudo/Main.java src/br/estudo/Testes.java
java -cp out br.estudo.Testes
java -cp out br.estudo.Main

7. Como interpretar os testes e as limitações

O teste distribuído confere doze casos do domínio, incluindo 7, 10, 7,5, 0, 6.99, nulo, vazio, texto, valor negativo, valor acima da faixa, NaN e Infinity. Uma falha lança AssertionError. A execução bem-sucedida escreve 12 verificações de domínio passaram. Esse teste independe de cliques e demonstra que a regra funciona sem a janela.

A apresentação exige uma conferência manual adicional. Use Tab, acione o botão com Enter, aumente a escala do sistema e leia os textos com a janela redimensionada. Confira se a mensagem muda depois de corrigir um erro. O teste do domínio não verifica a associação do rótulo, o foco nem a leitura por tecnologia assistiva. Registre separadamente o que foi automatizado e o que foi observado.

O laboratório trabalha em memória e não salva histórico. Fechar a janela encerra o processo. Antes de acrescentar uma lista persistente, defina o que precisa sobreviver ao fechamento e como uma falha de gravação será comunicada. Esse passo evita apresentar uma confirmação de salvamento quando o dado existe apenas num componente da tela.

8. Prática: evoluir o formulário sem perder a regra

Execute os doze testes e depois abra a janela. Confira uma aprovação, uma recuperação e três recusas. Acrescente um botão Limpar que esvazie o campo, restaure a mensagem inicial e devolva o foco. A ação não deve apagar dados externos, pois esta versão não possui armazenamento.

Como segunda atividade, inclua um nome de aluno obrigatório. Defina se espaços nas extremidades serão removidos e quais entradas devem ser recusadas. Coloque a validação numa função testável e apresente uma mensagem junto ao campo correspondente. Conclua quando o programa permanecer navegável por teclado e todas as entradas antigas continuarem com o mesmo resultado.

Para fazer esta prática com um ponto de partida que já compila, uma ferramenta que confere a interface sem abrir janela, um roteiro com a conferência manual e uma possível solução em pasta separada, baixe o laboratório de Swing do tema 16. Ele executa no seu computador, com JDK 17 ou superior; a janela exige ambiente gráfico, e nada disso executa no Playground.

Posso chamar Thread.sleep no listener para simular uma consulta?

Isso bloqueia a EDT e impede o processamento normal dos eventos durante a espera. Faça a simulação numa tarefa de fundo e atualize os controles na EDT quando o resultado chegar.
