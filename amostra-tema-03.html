1. Um roteiro para estudar textos com segurança

Você já sabe declarar variáveis e ler entradas. Agora precisa transformar o que recebeu em texto útil: distinguir um nome vazio de um nome ausente, comparar conteúdo, procurar uma palavra sem acessar um índice inválido e converter dados sem perder acentos. Esse conhecimento aparece em cadastros, mensagens, arquivos e APIs. Um detalhe aparentemente pequeno, como comparar referências em vez de conteúdo, pode mudar a decisão de um programa inteiro.

Estude este capítulo com um objetivo por exemplo. Primeiro escreva o que espera que apareça. Em seguida, execute o programa e explique qualquer diferença. Por último, mude uma entrada: nome vazio, espaços nas extremidades, letras em outra caixa ou um símbolo fora do alfabeto básico. Trabalhar com esses casos desde cedo evita criar soluções que só funcionam com a palavra “Java”.

  • Você vai praticar: igualdade, imutabilidade, índices, busca, transformação, conversão, Unicode, expressões regulares e codificação.
  • Pré-requisito: os temas 1 e 2, principalmente tipos, Scanner e o método main.
  • Ambiente: Java 17 como referência. Os laboratórios com strip, isBlank ou repeat exigem JDK 11 ou posterior; o compilador atual do Playground disponibiliza APIs de Java 8 e não inclui esses métodos.

Uma aplicação profissional precisa definir quais textos aceita e quais transformações preservam seu significado. Você não precisa antecipar todas as línguas em cada exercício, mas precisa conhecer os limites de uma regra simples. O caso de uso vem antes de escolher um método.

2. Texto é um objeto String

Uma String representa uma sequência de unidades de código UTF-16. É usada em nomes, mensagens, operações do menu e credenciais dos exercícios. Aspas duplas criam um literal de texto, como "Java"; aspas simples delimitam um char, como 'J'. Uma string pode estar vazia: "". Isso difere de null, que representa a ausência de uma referência a objeto. Chamar um método de instância através de uma referência nula pode causar NullPointerException.

A variável pode receber outro texto, mas o objeto String é imutável. Depois de criar uma string, seu conteúdo não é modificado por operações como replace ou toUpperCase. Esses métodos retornam um resultado que precisa ser usado. Em nome.toUpperCase();, o retorno é descartado; nome = nome.toUpperCase(); reatribui a variável. Entender esse comportamento evita procurar um erro de exibição quando o problema é um retorno ignorado.

3. Comparar conteúdo e comparar referências

== compara valores primitivos e, quando aplicado a referências, verifica se elas apontam para o mesmo objeto. equals, na classe String, compara o conteúdo. Duas strings com as mesmas letras podem ser objetos distintos. Alguns literais compartilham uma instância, e isso pode fazer um teste com == parecer correto por acaso. Para validar o nome de usuário de um exercício, use comparação de conteúdo.

String a = "Java";
String b = new String("Java");
System.out.println(a == b);       // false
System.out.println(a.equals(b));  // true
System.out.println("JAVA".equalsIgnoreCase(a)); // true

equalsIgnoreCase ignora diferenças entre maiúsculas e minúsculas conforme o comportamento da API. Não remova a diferença entre maiúsculas e minúsculas de uma senha sem que a regra do sistema determine isso. Para um valor que pode ser nulo, "admin".equals(usuario) evita chamar um método sobre a variável nula. Objects.equals(a, b) também compara referências possivelmente nulas de forma apropriada.

4. Índices e limites

length() devolve o comprimento em unidades UTF-16. O primeiro índice é zero e o último é length() - 1. Em "Java", os índices 0, 1, 2 e 3 correspondem a J, a, v e a. charAt(2) retorna 'v'. O índice 4 está fora desse texto. Antes de acessar a posição zero de uma entrada, verifique se ela está vazia.

Alguns caracteres, como determinados emojis, ocupam duas unidades UTF-16. Por isso, length() não é uma contagem universal de símbolos visíveis e charAt pode devolver somente parte da representação de um caractere. Os exemplos básicos usam palavras para que a relação entre índice e posição seja fácil de acompanhar. Ao tratar texto internacional em aplicações, considere pontos de código e a finalidade da contagem.

String linguagem = "Java";
System.out.println(linguagem.length());       // 4
System.out.println(linguagem.charAt(0));      // J
System.out.println(linguagem.substring(1, 3)); // av
System.out.println(linguagem.substring(2));   // va

substring(inicio, fim) inclui o índice inicial e exclui o final. Para obter "av", usamos as posições 1 e 2 e passamos 3 como limite. Índices negativos, início maior que o fim ou fim além do comprimento provocam erro. Anote as posições sobre o texto durante a revisão: isso torna visível o motivo de uma extração retornar uma letra a mais ou a menos.

5. Procurar e transformar

indexOf devolve a posição da primeira ocorrência ou -1 quando não encontra; lastIndexOf procura a última. A posição zero é um resultado válido. Portanto, texto.indexOf("Java") > 0 deixa de reconhecer a ocorrência no início; use >= 0 ou contains quando a pergunta for apenas sobre existência. startsWith e endsWith verificam prefixo e sufixo.

trim() remove, nas extremidades, caracteres abrangidos por sua regra de corte, não os espaços internos. replace('a', 'o') devolve uma string com as substituições. toLowerCase e toUpperCase convertem a caixa; a configuração regional pode importar. Para normalizar identificadores técnicos em uma regra independente da região, forneça Locale.ROOT. Preservar acentos e grafias de nomes de pessoas costuma ser mais apropriado do que aplicar uma transformação geral.

String entrada = "  Java para o grupo  ";
String limpa = entrada.trim();
System.out.println(limpa);
System.out.println(limpa.contains("Java"));
System.out.println(limpa.indexOf("grupo"));
System.out.println(limpa.replace("grupo", "estudo"));

compareTo oferece uma ordenação lexicográfica baseada na representação das strings. Um resultado negativo indica que a primeira vem antes, zero indica igualdade de conteúdo e um positivo indica que vem depois. A magnitude não deve ser interpretada como distância entre palavras. Ordenação linguística de nomes, considerando regras de um idioma, exige uma ferramenta apropriada, como Collator.

6. Concatenar, converter e montar mensagens

+ concatena quando a expressão passa a envolver texto. concat também pode juntar strings. Para pequenas mensagens, "Olá, " + nome é legível. Em uma montagem repetida de texto, StringBuilder permite acumular partes em um objeto mutável e obter a string final com toString(). O motivo para escolhê-lo deve acompanhar o trabalho realizado, em vez de acrescentá-lo a toda mensagem simples.

StringBuilder resultado = new StringBuilder();
for (int i = 1; i <= 3; i++) {
    resultado.append("Item ").append(i).append('\n');
}
System.out.print(resultado.toString());

Converter um número em texto e converter texto em número são operações diferentes. String.valueOf(42) produz uma representação textual. Integer.parseInt("42") produz um inteiro. Se o texto for "quarenta", a conversão inteira falha. Double.parseDouble espera a sintaxe numérica da API, com ponto decimal; ele não aplica automaticamente o mesmo tratamento regional de um Scanner configurado para português.

7. Login didático e cuidado com a regra

static boolean validarLogin(String usuario, String senha) {
    return "admin".equals(usuario) && "12345".equals(senha);
}

Esse método devolve um booleano e permite estudar parâmetros, comparação de texto e &&. A própria condição pode ser retornada, sem uma cadeia de if que apenas devolva verdadeiro ou falso. Se o usuário autorizado é admin, uma tentativa com Luna deve ser recusada. A comparação precisa seguir a regra declarada pelo método.

Credenciais fixas no código são usadas aqui apenas para o exercício. A atividade não fornece autenticação de produção, persistência segura ou proteção de contas reais. Use dados fictícios no Playground. A comparação pode ajudar a entender o fluxo, mas não substitui uma arquitetura de autenticação apropriada em uma aplicação publicada.

8. Construir texto a partir de caracteres e bytes

Além dos literais, os construtores de String aceitam fontes de dados como arrays de caracteres e bytes. new String(new char[]{'J', 'a', 'v', 'a'}) produz o texto Java. Há sobrecargas que recebem posição inicial e quantidade de elementos: esse segundo número é um comprimento, diferente do limite final excluído usado em substring. Confira qual convenção o método ou construtor escolhido utiliza antes de adaptar os índices.

char[] letras = {'J', 'a', 'v', 'a'};
String palavra = new String(letras);
byte[] bytes = palavra.getBytes(java.nio.charset.StandardCharsets.UTF_8);
String reconstruida = new String(bytes, java.nio.charset.StandardCharsets.UTF_8);
System.out.println(reconstruida); // Java

Caracteres e bytes não são a mesma unidade. Uma codificação, como UTF-8, define como o texto é representado em bytes. Ao ler ou gravar dados, informe a mesma codificação nos dois sentidos; escolher configurações incompatíveis pode corromper a apresentação de acentos. O construtor que recebe apenas bytes usa a codificação padrão do ambiente, o que pode produzir diferenças entre computadores. O exemplo informa UTF-8 explicitamente para evitar essa dependência.

9. Exercícios para verificar compreensão

Receba um nome, remova espaços das extremidades e imprima a primeira letra somente quando houver texto. Compare duas entradas com equals e explique o caso de caixa diferente. Para "programacao", marque os índices e extraia "grama" antes de executar. Depois procure um termo inexistente e verifique por que o retorno -1 precisa ser tratado antes de virar um índice.

Revise os exemplos da apostila com atenção às aspas tipográficas e à posição das chaves: copiar um código diagramado pode trazer caracteres que não são delimitadores Java. No Playground, a atividade de textos oferece código executável; o login didático relaciona strings a métodos e decisões.

10. Vazio, espaço em branco e ausência são estados diferentes

Use três perguntas separadas ao receber um campo: ele existe? Existe algum conteúdo? O conteúdo atende à regra? Uma referência null não aponta para String alguma. Uma string vazia existe e tem comprimento zero. Um texto com três espaços também existe e tem comprimento maior que zero. Para um nome obrigatório, os três casos podem ser recusados, mas por motivos diferentes.

A ordem da validação importa. Em nome == null || nome.trim().isEmpty(), o curto-circuito impede chamar trim quando nome é null. Inverter a expressão retiraria essa proteção. O método trim não deve ser tratado como uma limpeza universal de Unicode; no JDK 11+, strip e isBlank usam outra definição de espaço. Mesmo essa definição não cobre toda convenção possível de separação de texto.

Não use automaticamente String.valueOf(valor) para esconder uma ausência: com uma referência nula, o resultado pode ser o texto “null”, que ainda não é um nome válido. Da mesma maneira, a string literal “null” digitada por uma pessoa não é a referência null. O contrato do campo deve dizer qual estado representa ausência.

11. Igualdade, literais compartilhados e imutabilidade na prática

Um literal pode compartilhar uma instância com outro literal equivalente. Essa característica pode fazer uma comparação com == passar em um teste pequeno e falhar quando o texto vem de Scanner ou de um arquivo. O contrato de comparação precisa ser igualdade de conteúdo, independentemente de onde o objeto foi criado. Evite usar new String apenas para “garantir uma cópia” de texto imutável; aqui ele serve para tornar a diferença observável.

Os colchetes da saída deixam os espaços visíveis. O objeto original continua representando o mesmo texto; limpa recebe o resultado da operação. Reatribuir original também seria possível, mas isso mudaria a referência guardada pela variável, não o conteúdo de uma String já criada. Ao encadear transformações, use o resultado final e mantenha um nome claro para o dado que será apresentado.

Não use intern como correção para uma comparação errada. Isso acrescenta dependência de compartilhamento sem resolver a intenção. Para comparar o texto de duas referências possivelmente nulas, Objects.equals expressa essa intenção. Para uma operação que exige texto presente, valide a ausência e apresente o erro adequado.

12. Definir o intervalo antes de recortar

Ao extrair um trecho, desenhe uma marca entre os caracteres. Em Java, a faixa de substring começa em uma dessas marcas e termina antes da marca final. Isso permite calcular o tamanho por fim menos início. Um trecho vazio com início igual ao fim é válido, inclusive na marca imediatamente depois do último char. Já um limite além dessa marca é inválido.

Para uma extração orientada por busca, trate primeiro o caso em que o separador não aparece. Imagine a entrada “nome=Ana”. O índice do sinal de igualdade é 4; o nome do campo ocupa [0,4), e o valor começa em 5. Se a entrada for “Ana”, indexOf devolve −1. Somar ou usar esse resultado como se o separador existisse cria um processamento diferente do pretendido.

Esse programa aceita apenas uma separação simples e permite valor vazio. Se a regra exigir campo e valor obrigatórios, valide ambos após o recorte. Se houver mais sinais de igualdade, defina se eles pertencem ao valor ou se devem ser recusados. Não transforme um formato pequeno em um parser geral sem definir primeiro sua gramática.

13. UTF-16, pontos de código e o que significa contar caracteres

Na palavra Java, o número de letras, de unidades UTF-16 e de pontos de código coincide. Isso não vale para todo texto. Um emoji suplementar pode ocupar duas unidades UTF-16. Uma letra acentuada também pode ter uma forma composta ou uma sequência de letra e acento. Antes de limitar um campo a “dez caracteres”, diga que unidade a regra realmente pretende limitar.

O laboratório usa escapes para que você consiga digitar o mesmo exemplo em qualquer editor. Os índices de substring continuam sendo índices UTF-16; offsetByCodePoints ajuda a encontrar a posição sem dividir o par substituto. Isso ainda não conta agrupamentos visuais complexos como emojis com modificadores ou sequências ligadas. Pontos de código e símbolos percebidos por uma pessoa são conceitos diferentes.

Quando a operação precisar percorrer pontos de código, uma estratégia é avançar pelo tamanho de cada ponto com Character.charCount. Quando precisar de segmentação visual ou linguística, investigue as ferramentas adequadas e teste os idiomas do produto. Não improvise o recorte de nomes internacionais com charAt(0) e suponha que ele sempre representa uma letra inteira. A API de Character explica a representação usada pela plataforma.

14. Normalização Unicode e diferenças de maiúsculas

Dois textos podem parecer iguais e usar sequências Unicode diferentes. Ao comparar conteúdo recebido de fontes diferentes, uma regra pode escolher uma forma canônica, como NFC. Isso não é o mesmo que remover acentos: normalizar preserva equivalências específicas; transformar “José” em “Jose” é outra decisão, que pode apagar uma distinção importante.

Para chaves técnicas cujo contrato seja independente do idioma, Locale.ROOT evita depender da região padrão da máquina em uma conversão de caixa. Para texto de uma interface em português, uma localização explícita pode fazer mais sentido. Escolher a região é parte do requisito. Não transforme senhas em minúsculas nem remova seus espaços sem uma regra de autenticação que defina esse comportamento.

Nem normalização nem equalsIgnoreCase são uma defesa geral contra nomes visualmente confundíveis. Se um identificador público precisa ser único, defina um conjunto aceito e uma política de comparação. Nomes de exibição podem preservar a escrita original enquanto uma chave de pesquisa usa um tratamento definido separadamente. A documentação de Normalizer descreve as formas suportadas.

15. Texto literal e expressão regular não são a mesma linguagem

Uma expressão regular é um padrão de busca com regras próprias. Isso muda o significado de certos caracteres: o ponto representa uma categoria de correspondência, não necessariamente um ponto literal. Antes de escolher replaceAll, pergunte se você precisa de um padrão ou de uma substituição literal. Para trocar uma palavra exata por outra, replace costuma expressar melhor a intenção.

String codigo = "a.b.c";
System.out.println(codigo.replace(".", "-")); // a-b-c
System.out.println(codigo.replaceAll(".", "-")); // -----
System.out.println(codigo.replaceAll("\\.", "-")); // a-b-c

Na última linha, o fonte Java precisa representar uma barra invertida no texto entregue ao mecanismo de regex. Você está escrevendo em duas camadas: literal Java e padrão. Se o padrão vem de um texto que deve ser tratado literalmente, Pattern.quote é uma alternativa. Na substituição de uma regex, dólar e barra também têm significado; Matcher.quoteReplacement ajuda a preservar uma substituição literal.

matches procura correspondência para a entrada inteira. find, em Matcher, localiza um trecho. Uma regra de código com duas letras ASCII maiúsculas e três dígitos pode usar [A-Z]{2}[0-9]{3}. Isso não é uma regra apropriada para nomes de pessoas: nomes têm convenções muito mais amplas. A API de Pattern deve acompanhar o padrão que você realmente pretende aceitar.

16. Separar campos sem perder o último valor vazio

Split recebe uma expressão regular. Separar por ponto pede cuidado com seu significado no padrão. Além disso, o comportamento de descarte de campos vazios finais pode esconder um dado ausente. Se o formato “nome;cidade;email” precisa sempre ter três campos, preservar o último vazio permite identificar um email ausente em vez de confundir o tamanho do registro.

O limite negativo preserva campos vazios ao final. Depois, valide a quantidade de campos e a regra de cada posição. Esse exercício não implementa CSV completo: aspas, quebras de linha internas e separadores dentro de um campo exigem um formato e um parser adequados. Quando o dado vem de um sistema externo, prefira seu formato especificado a uma sequência de splits improvisados.

String.join reúne elementos usando um delimitador, mas não escapa delimitadores contidos nos próprios dados. Juntar e separar nem sempre são operações inversas. Teste um valor que contenha o separador escolhido antes de adotar esse formato para armazenamento.

17. Conversão de texto: validade sintática e validade da regra

Um texto pode representar um inteiro válido e ainda ser uma quantidade proibida. -3 pode ser convertido, mas não é uma quantidade aceitável de livros emprestados. “999999999999999999999” usa dígitos, porém não cabe em int. Uma validação robusta separa leitura, conversão, intervalo permitido e cálculo.

Não compare uma String numericamente por ordem lexicográfica. Na ordenação textual, “100” pode aparecer antes de “20”, porque a primeira posição já decide a comparação. Se o campo representa um número, interprete-o com a conversão adequada e trate a falha. Se representa um identificador, preserve o texto e seus zeros iniciais.

Teste novamente com “quarenta”, uma string vazia, um número fora do intervalo e um número maior que int. Não capture Exception apenas para esconder qualquer problema do programa; aqui, o erro esperado é NumberFormatException. Uma falha de entrada deve produzir uma orientação útil e não continuar usando um valor substituto silencioso.

18. Construir mensagens sem misturar apresentação e dado

Uma mensagem de apresentação pode juntar nome, quantidade e unidade. O valor usado no cálculo não deve ser substituído cedo demais por um texto formatado. Conserve o número para operar e formate quando for mostrá-lo. Se o relatório usa uma região específica, informe-a em printf ou na ferramenta apropriada.

Para poucas partes, + é claro. Em uma montagem repetida, StringBuilder permite acrescentar partes sem exigir que você descreva uma nova String a cada iteração. O importante é saber quando o resultado é produzido e não compartilhar um builder mutável sem coordenação entre tarefas. StringBuilder não torna automaticamente uma operação concorrente segura.

O texto pronto pode ser guardado ou apresentado. Se depois você modificar o builder, a String já obtida continua imutável. Para montar uma lista já disponível, String.join pode ser mais direto do que um laço. Não acrescente builder a toda concatenação curta por uma promessa genérica de desempenho: legibilidade e o trabalho real importam.

No JDK 17, text blocks ajudam a escrever textos de várias linhas, mas ainda exigem compreender escapes e a organização das linhas. Eles não executam automaticamente expressões embutidas no texto. Evite apresentar sintaxe de versões diferentes sem dizer qual compilador e qual API são necessários.

19. Bytes, UTF-8 e tratamento de dados malformados

Quando texto atravessa um arquivo, uma rede ou um banco, ele pode ser representado por bytes. A codificação determina como interpretá-los. Usar UTF-8 para gravar e outra codificação para ler pode produzir uma apresentação errada mesmo que os bytes tenham sido transportados sem alteração. Declare o formato no contrato da integração.

Uma conversão simples de bytes pode substituir sequências malformadas por um caractere de substituição. Quando o contrato exigir recusar dados inválidos, use um decodificador configurado para reportar o problema. Essa escolha evita aceitar silenciosamente um texto diferente do que a origem pretendia fornecer.

A primeira parte demonstra uma ida e volta com a mesma codificação. A segunda fornece uma sequência deliberadamente inválida para provar a regra de recusa. Esse laboratório não altera arquivos nem tenta consertar automaticamente o dado. Se precisar guardar o erro para investigação, tome cuidado com informações pessoais: registre o necessário para diagnosticar sem divulgar o conteúdo recebido.

Confira a API de CharsetDecoder ao decidir como uma integração tratará entradas malformadas. O mesmo raciocínio vale para saídas: documentar o formato evita depender da configuração de uma máquina específica.

20. Laboratório integrado: receber e apresentar um nome

Crie um programa que leia uma linha como nome de exibição. A regra deste laboratório é: recusar entrada ausente ou composta apenas de espaços; remover espaços nas extremidades; preservar os espaços internos e as letras digitadas; exibir o nome tratado e a quantidade de pontos de código. Não converta o nome para caixa alta nem remova acentos. Este exercício trata texto, não certifica a identidade da pessoa.

Use Ana Silva na entrada. Depois teste uma linha vazia, somente espaços e fim de entrada sem linhas. São três estados diferentes. Para testar no Playground atual, adapte strip para trim e isBlank para isEmpty, explicando que essa adaptação muda a abrangência de espaços reconhecidos. Não anuncie as duas versões como equivalentes para todo Unicode.

O limite de tamanho de um cadastro dependeria de outros requisitos, como armazenamento e interface; este laboratório não inventa esse limite. O objetivo é mostrar uma transformação pequena e explícita. Ao evoluir o programa, acrescente a regra de tamanho e seus testes antes de aplicar um corte que possa apagar parte do nome.

21. Prática progressiva com enunciados completos

Nos exercícios abaixo, comece escrevendo seu código. Consulte a solução somente depois de prever uma saída e tentar reproduzi-la. Cada programa deve ter public class Main e o método principal. Use JDK 17 para executar todos os exemplos sem as limitações de biblioteca do Playground.

  1. Recorte: declare a string literal “programacao”. Numere suas posições de 0 a 10 no papel. Extraia apenas “grama” usando substring, sem substituir caracteres. Imprima o trecho em uma única linha. Faça uma segunda previsão para a mesma operação com o limite final diminuído em 1.
  2. Comparação: declare um literal “Java” e uma nova String com o mesmo conteúdo. Imprima primeiro a comparação por referência e depois a comparação por conteúdo. Explique por que as respostas diferem. Não use intern para alterar o resultado.
  3. Campo obrigatório: leia uma linha. Se não houver linha, informe “Nome ausente.”. Se houver somente espaços, informe “Informe um nome com conteúdo.”. Nos demais casos, imprima o nome sem espaços nas extremidades. Preserve os espaços internos. Teste os três caminhos separadamente.
  4. Registro simples: use “Ana;Recife;”. Separe por ponto e vírgula preservando o campo final vazio. Confira que existam três campos antes de acessar o terceiro. Imprima “Email ausente” para esse registro. O exercício não aceita campos com ponto e vírgula embutido.
  5. Conversão: adapte o programa de quantidade para aceitar apenas valores de 1 a 20, inclusive. Teste 1, 20, 0, 21, “abc” e uma string vazia. Para cada teste, escreva a mensagem esperada antes de executar.
Possível solução: recortar grama

O índice inicial é 3; o final é 8 e não participa do trecho. Com fim 7, a saída é gram. Contar o tamanho esperado, cinco letras, ajuda a conferir 8 menos 3.

Possível solução: registro simples

A validação do tamanho protege o acesso à posição 2. Preservar o campo final permite diferenciar ausência de conteúdo de um formato com quantidade errada de posições.

Conferir as demais respostas e os critérios

A comparação do segundo exercício produz false e true, como no laboratório de igualdade. O exercício de nome pode usar a validação do laboratório integrado; a diferença é que você pode omitir a contagem. No exercício de quantidade, substitua a condição por quantidade < 1 ou quantidade > 20. Os valores 1 e 20 são aceitos; 0 e 21 são recusados por intervalo; abc e o texto vazio falham na conversão.

Considere a atividade compreendida quando conseguir explicar o comportamento sem citar apenas “porque o Java faz assim”. Identifique a unidade do índice, o tipo da comparação, a transformação executada e a regra que decide aceitar ou recusar uma entrada.

22. Revisão para avançar e usar o conhecimento em um projeto

Antes de continuar, explique estas diferenças com um exemplo seu: null e string vazia; == e equals; índice UTF-16 e ponto de código; replace e replaceAll; texto e bytes; transformação e validação. Se você precisar executar para adivinhar todas as respostas, volte aos laboratórios e faça previsões menores.

Em um projeto de cadastro, comece definindo os campos e suas regras. Preserve um nome de exibição quando a regra pedir; normalize apenas a chave que realmente exige normalização; registre a codificação da integração; apresente erros que permitam corrigir a entrada. Uma sequência de métodos encadeados sem um contrato pode apagar dados importantes e parecer correta nos testes mais fáceis.

Para continuar, o tema 4 organiza decisões com if e switch. Os temas de arquivos e persistência retomam a travessia entre bytes e texto. O tema de coleções mostra por que igualdade e hashCode afetam a busca de chaves. Você não precisa antecipar todas essas implementações agora, mas pode reconhecer que os fundamentos deste capítulo reaparecem em cada camada.
