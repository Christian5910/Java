1. Organizar dados exige escolher o que cada posição significa

Quando um programa precisa guardar várias notas, criar nota1, nota2 e nota3 resolve apenas um tamanho fixo muito pequeno. Um array permite aplicar o mesmo algoritmo a várias posições, mas não decide por você o que cada posição representa. Antes de implementar, descreva se a ordem importa, se valores repetidos são permitidos, se pode haver ausência e qual operação será mais comum.

Um índice não é automaticamente um identificador permanente. Se você ordenar alunos, a posição de cada um pode mudar; se precisa encontrá-los por matrícula, a busca exige outra relação. Não trate o índice visual de uma lista como identidade do registro. Esse cuidado começa aqui e reaparece em coleções, arquivos e bancos de dados.

Para acompanhar este tema, você precisa dos laços e das condições anteriores. Ao final, deverá percorrer arrays sem ultrapassar limites, distinguir compartilhamento de cópia, trabalhar com linhas de comprimentos diferentes e escolher entre List, Set e Map por seu contrato. Os programas usam dados pequenos para que você consiga conferir cada transformação manualmente.

2. Armazenar vários valores relacionados

Um array agrupa elementos de um mesmo tipo e oferece acesso por índice. Em vez de criar nota1, nota2 e muitas variáveis semelhantes, podemos usar double[] notas. Cada posição guarda um valor do tipo declarado. O array tem comprimento fixo depois de criado; a variável que o referencia pode receber outro array, mas isso não redimensiona o objeto anterior.

Arrays são objetos. Declarar int[] numeros; cria uma variável por referência, ainda sem um array utilizável se ela for local e não tiver sido inicializada. new int[3] cria um array com três posições. A definição de Java não exige que o estudante raciocine sobre endereços físicos contíguos para usá-lo; os acessos são feitos pelos índices e pelos limites da linguagem.

3. Criar, inicializar e acessar

int[] numeros = new int[3];
numeros[0] = 10;
numeros[1] = 20;
numeros[2] = 30;
System.out.println(numeros[1]); // 20

double[] notas = {6.0, 7.0, 8.0};
System.out.println(notas.length); // 3

O índice inicial é zero. Em um array de comprimento 3, os índices válidos são 0, 1 e 2. numeros[3] provoca ArrayIndexOutOfBoundsException. Índices negativos também são inválidos. length é um campo do array e não leva parênteses; length() é um método de String. Use vetor.length para arrays e texto.length() para strings.

Quando o array é criado, elementos numéricos recebem zero, booleanos recebem falso, caracteres recebem '\u0000' e referências recebem null. Um array de String recém-criado contém referências nulas, não textos vazios. Um array de comprimento zero é válido, mas não tem uma posição zero. Antes de usar o primeiro elemento como ponto de partida para um menor valor, confira se existe ao menos um elemento.

4. Percorrer com for e for-each

int[] numeros = {10, 20, 30};
for (int i = 0; i < numeros.length; i++) {
    System.out.println("Posição " + i + ": " + numeros[i]);
}
for (int numero : numeros) {
    System.out.println(numero);
}

O primeiro laço oferece o índice, útil para alterar posições ou relacionar dois arrays. O segundo percorre os valores e facilita a leitura quando o índice não é necessário. A variável numero recebe o valor da posição atual. Reatribuir essa variável primitiva não altera o elemento do array. Para dobrar todos os inteiros, use numeros[i] *= 2 em um laço com índices.

Quando os elementos são referências a objetos, o for-each copia a referência para a variável de iteração. Um método chamado nesse objeto pode mudar seu estado; reatribuir a variável de iteração para outro objeto não substitui a posição do array. Essa diferença retoma a distinção entre mudar o objeto e mudar a referência.

5. Soma, média e menor valor

double[] notas = {6.0, 7.0, 8.0};
double soma = 0;
for (double nota : notas) {
    soma += nota;
}
if (notas.length == 0) {
    System.out.println("Sem notas");
} else {
    double media = soma / notas.length;
    System.out.printf(java.util.Locale.US, "Média: %.2f%n", media);
}

O acumulador fica antes do laço e o cálculo da média fica depois de somar todos os elementos. A verificação do comprimento evita uma divisão sem significado para uma coleção vazia. Se precisar do menor inteiro, inicialize o candidato com o primeiro elemento e compare os seguintes. Começar o menor em zero daria um resultado incorreto para um conjunto formado apenas por números positivos.

O algoritmo de busca também deve informar o caso em que não encontra um valor. Você pode iniciar a posição com -1 e substituí-la quando encontrar. Isso evita confundir o índice zero com ausência. Defina se deseja a primeira ocorrência ou todas as ocorrências: usar break após encontrar a primeira encerra a busca.

6. Compartilhar, copiar e ordenar

int[] original = {3, 1, 2};
int[] mesmaReferencia = original;
mesmaReferencia[0] = 9;
System.out.println(original[0]); // 9

int[] copia = java.util.Arrays.copyOf(original, original.length);
java.util.Arrays.sort(copia);
System.out.println(java.util.Arrays.toString(copia));

A atribuição de um array para outra variável copia a referência. As duas variáveis passam a acessar o mesmo objeto. Arrays.copyOf cria outro array; para elementos por referência, a cópia continua apontando para os mesmos objetos internos, uma cópia superficial. Arrays.sort altera a ordem do array fornecido. Se a ordem original precisa ser mantida, ordene uma cópia.

Arrays.toString gera uma apresentação dos elementos de um array unidimensional. Imprimir diretamente uma referência de array com println não produz, em geral, a listagem dos elementos esperada pelo iniciante. Para arrays aninhados, Arrays.deepToString oferece uma representação das estruturas internas. Comparação de conteúdo também exige uma operação apropriada, como Arrays.equals, em vez de comparar referências com ==.

7. Matrizes são arrays de arrays

int[][] matriz = {
    {1, 2, 3},
    {4, 5, 6}
};
for (int linha = 0; linha < matriz.length; linha++) {
    for (int coluna = 0; coluna < matriz[linha].length; coluna++) {
        System.out.print(matriz[linha][coluna] + " ");
    }
    System.out.println();
}

matriz.length informa a quantidade de linhas, e matriz[linha].length informa o comprimento da linha atual. Java permite linhas de comprimentos diferentes. Portanto, usar sempre o comprimento da primeira linha só é seguro quando o programa garante uma estrutura retangular. Uma linha também pode ser nula em estruturas parcialmente inicializadas; é preciso inicializá-la antes de acessar seus elementos.

No exemplo, matriz[1][2] vale 6. Para somar uma coluna, percorra as linhas e confirme que a coluna existe em todas elas. Para somar a diagonal principal de uma matriz quadrada, os índices de linha e coluna coincidem. Desenhar a tabela e escrever os índices nas bordas ajuda a traduzir o raciocínio para os dois acessos entre colchetes.

8. Quando uma lista é mais adequada

ArrayList é um complemento de estudo para coleções cuja quantidade de itens varia. ArrayList<String> pode receber novos nomes com add, consultar com get e informar o tamanho com size(). Os índices continuam começando em zero. Uma lista de inteiros usa Integer, não int, no parâmetro genérico. Arrays continuam úteis quando o tamanho e o acesso indexado já representam bem o problema.

Uma lista também pode reunir contas para que o programa procure uma delas pelo número. Isso conecta estruturas de dados à organização em classes, estudada a seguir. Comece com uma busca por laço e teste um número existente e outro inexistente. Escolha outra estrutura quando a forma de consulta justificar a mudança.

9. Generics e os tipos aceitos por uma coleção

Em List<String>, o parâmetro genérico informa que a lista recebe referências compatíveis com String. Tentar adicionar um inteiro produz um erro de compilação e evita descobrir esse engano apenas na leitura. Tipos primitivos não são parâmetros genéricos: uma lista de números inteiros usa Integer. A conversão automática entre int e Integer é chamada de boxing ou unboxing, conforme a direção.

Essa conveniência não elimina a possibilidade de null. Desempacotar um Integer nulo para int causa NullPointerException. Também não torna List<Integer> um subtipo de List<Number>: permitir essa atribuição abriria espaço para inserir outros números na lista original de inteiros. Evite os tipos crus, como List sem parâmetro, porque eles perdem verificações úteis. Os fundamentos de generics explicam como os parâmetros relacionam entradas e saídas de uma API.

10. Escolher entre List, Set e Map

Depois dos arrays, escolha uma coleção pela operação necessária. List representa uma sequência com posições e pode conter repetições. Set representa elementos sem duplicação segundo sua regra de igualdade. Map associa uma chave a um valor; inserir novamente a mesma chave substitui o valor associado. Map faz parte do framework de coleções, mas não estende Collection.

Estruturas para um cadastro de estudo
NecessidadeTipoCuidado
Preservar a sequência de nomes, inclusive repetidos.List<String>Posições mudam quando itens são inseridos ou removidos.
Registrar nomes distintos.Set<String>A implementação define se há uma ordem de iteração.
Consultar uma nota pelo nome.Map<String, Integer>Nomes iguais compartilham a mesma chave nesse modelo.

ArrayList permite acesso por índice e cresce conforme necessário. HashSet e HashMap não prometem a ordem de inserção; para demonstrar resultados nessa ordem, o exemplo usa LinkedHashSet e LinkedHashMap. TreeSet e TreeMap trabalham com ordenação segundo comparação. Uma LinkedList não torna toda inserção automaticamente barata: localizar uma posição também tem custo. Comece pela estrutura cuja regra é clara e só investigue desempenho com uma necessidade concreta.

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        List<String> presencas = new ArrayList<>();
        presencas.add("Ana");
        presencas.add("Bruno");
        presencas.add("Ana");
        Set<String> pessoas = new LinkedHashSet<>(presencas);
        Map<String, Integer> notas = new LinkedHashMap<>();
        notas.put("Ana", 7);
        notas.put("Bruno", 8);
        notas.put("Ana", 9);
        System.out.println(presencas);
        System.out.println(pessoas);
        System.out.println(notas);
        System.out.println(notas.containsKey("Carla"));
    }
}

Praticar este programa no Playground

O programa apresenta [Ana, Bruno, Ana], depois [Ana, Bruno], depois {Ana=9, Bruno=8} e, por último, false. Compare a repetição mantida pela lista com a unicidade do conjunto e a substituição no mapa. Uma chave ausente pode fazer get devolver null; não trate isso como nota zero sem que o contrato defina essa equivalência. Use containsKey quando precisar distinguir ausência. Consulte os contratos de List, Set e Map.

Strings com o mesmo conteúdo são consideradas iguais por equals e possuem códigos de hash compatíveis. Essa regra permite procurar um nome textual em um HashMap mesmo usando outra instância de string com os mesmos caracteres. Para classes próprias usadas como chaves, igualdade e hashCode devem ter contratos compatíveis. Evite alterar campos que participam da igualdade enquanto o objeto estiver em uma estrutura de hash: a busca pode deixar de localizar a chave como esperado.

Uma chave de cadastro também precisa de uma regra de normalização explícita. Se “Ana” e “ana” representam a mesma pessoa no exercício, normalize as entradas de modo consistente antes de gravar e consultar, ou adote outra chave estável. Não aplique essa transformação por hábito em senhas, textos de exibição ou dados cujo significado depende da grafia original. O exercício de normalização permite observar essas escolhas antes de usar um mapa.

11. Prática e casos de borda

Calcule soma e média de notas, encontre o menor elemento e busque a posição de um número. Teste array vazio, array com um elemento e valores repetidos. Em uma matriz, some cada linha e confira a diferença entre número de linhas e número de colunas. Faça uma cópia, altere apenas a cópia e explique por que uma atribuição simples teria outro efeito.

Abrir arrays, percorrer uma matriz e experimentar uma lista. Ao revisar, verifique se cada índice é menor que o comprimento da estrutura que está sendo acessada.

12. Array vazio, referência nula e posição não preenchida

Um array vazio existe e tem comprimento zero. Uma referência nula não aponta para array algum. Um array de referências recém-criado pode existir com todas as posições nulas. Esses três estados levam a verificações diferentes: length é válido no vazio, mas não em null; uma posição dentro dos limites ainda pode não conter um objeto.

Não inicie menor valor por notas[0] antes de conferir que há ao menos uma posição. A condição índice menor que length também não protege contra um índice negativo; se ele vier de uma entrada externa, confira os dois limites. O contrato do método deve dizer se null é uma entrada recusada ou uma representação aceita de ausência.

Capacidade e quantidade utilizada podem ser diferentes. Um array de tamanho 100 reservado para um cadastro não contém automaticamente 100 pessoas cadastradas. Se você mantiver esse modelo manualmente, precisará controlar a quantidade usada. Quando o tamanho lógico varia, uma lista frequentemente representa melhor a necessidade.

13. For-each não substitui qualquer percurso por índice

For-each facilita visitar os valores quando a posição não participa da operação. A variável do laço recebe um valor de cada elemento; atribuir outro valor a essa variável não substitui a posição do array. Se o objetivo é dobrar todos os inteiros armazenados, escreva uma atribuição à posição correspondente.

Com objetos mutáveis, o valor copiado pelo for-each é uma referência. Chamar um método que altera esse objeto pode modificar o estado observado por outras referências, mesmo sem substituir a posição. Isso não contradiz a passagem por valor: o valor copiado é a referência, e o objeto continua compartilhado.

Escolha o percurso pelo trabalho necessário: use índice para posição, vizinhos ou substituição; use for-each quando cada valor é suficiente. Evite acrescentar um contador paralelo a todo for-each, pois isso tende a esconder uma necessidade que um for tradicional já expressaria diretamente.

14. Soma, média e extremos com contrato explícito

Uma rotina de estatísticas precisa definir o resultado para uma sequência vazia e quais números aceita. Neste laboratório, o array não pode ser nulo, precisa ter ao menos um elemento e deve conter somente valores finitos. A soma também deve continuar finita. Uma média com NaN não é uma forma adequada de comunicar que uma nota estava ausente.

Começar menor em zero seria incorreto para dados todos positivos: zero poderia aparecer como mínimo sem pertencer à entrada. Usar o primeiro elemento após validar o tamanho estabelece um candidato real. Faça também um teste com todos os valores negativos para detectar uma inicialização indevida do maior.

Este cálculo é adequado ao laboratório, mas não promete precisão perfeita para qualquer conjunto de doubles. Somar números de magnitudes muito diferentes pode perder informação por arredondamento. Quando a aplicação exigir outra precisão, escolha um algoritmo numérico e uma representação adequados ao domínio, em vez de supor que mais casas na impressão resolvem o cálculo.

15. Buscar preservando o significado de não encontrado

Uma busca linear visita elementos até encontrar o que procura ou chegar ao fim. Se precisa apenas da primeira ocorrência, pode encerrar ao encontrá-la. Se precisa da última, deve continuar e atualizar o candidato. O valor -1 é uma sentinela útil para índice ausente porque nenhum índice válido é negativo.

Não use zero como ausência: a primeira posição também tem índice zero. Não transforme automaticamente um retorno -1 em um acesso ao array. O chamador precisa interpretar a sentinela antes de usar o resultado. Em um método, documente se procura a primeira ocorrência, qualquer ocorrência ou todas as ocorrências.

Para n elementos, a busca linear pode precisar visitar todos. Uma busca binária exige uma organização ordenada compatível com a comparação. Aplicá-la a uma sequência arbitrária não é uma otimização válida. Além disso, ordenar antes pode mudar a posição original que o usuário pretendia consultar. Considere todo o contrato, não apenas a quantidade de comparações.

16. Ordenar, copiar e comparar são operações diferentes

Atribuir b = a compartilha o mesmo array. Copiar com Arrays.copyOf cria outra estrutura. Ordenar com Arrays.sort modifica a estrutura recebida. Para mostrar um relatório ordenado sem perder a sequência original, copie e ordene a cópia. Arrays.equals compara o conteúdo dos elementos; == compara se as referências apontam para o mesmo array.

Arrays.copyOf pode copiar para um tamanho diferente, completando posições adicionais com valores padrão ou descartando posições finais. Não use essa mudança de tamanho como uma política implícita de descarte de dados. Quando reduzir uma coleção de registros, o contrato deve dizer quais elementos serão preservados e se a perda é aceitável.

Em arrays de objetos, a cópia é superficial: as posições novas guardam referências para os mesmos elementos. Em matrizes, copiar apenas o array externo ainda compartilha as linhas. Independência da estrutura não implica independência de todos os objetos alcançáveis a partir dela. O próximo laboratório torna essa diferença visível sem depender de um desenho de endereços físicos.

17. Matrizes irregulares e cópia de linhas

Um int[][] é um array cujos elementos referenciam outros arrays. As linhas podem ter comprimentos diferentes e até ser nulas. Se o contrato permitir essa forma, percorra cada linha por seu próprio length e decida explicitamente o que uma linha nula representa. Se o método exigir uma matriz retangular, valide essa exigência antes de calcular com um único número de colunas.

O valor 9 aparece no original porque a primeira linha continua compartilhada na cópia superficial. Já o 7 fica apenas na matriz com linhas copiadas. Este laboratório usa somente linhas presentes e inteiros; uma rotina geral precisaria definir como tratar linhas nulas e objetos mutáveis dentro delas.

Para transpor uma matriz retangular m por n, crie uma matriz n por m e atribua destino[coluna][linha] a partir de origem[linha][coluna]. Confira as dimensões antes do acesso à primeira linha, especialmente no caso vazio. Uma matriz irregular não tem uma transposição retangular única sem uma regra de preenchimento ou de recusa.

18. List, Set e Map: escolha pelo comportamento que precisa preservar

List mantém uma sequência de elementos e permite repetições; Set representa unicidade segundo as regras de igualdade da implementação; Map associa chaves a valores. Esses contratos descrevem papéis distintos. Um Map não é uma lista com índices especiais, e uma lista não elimina duplicados automaticamente.

A ordem de iteração depende da implementação. LinkedHashSet e LinkedHashMap ajudam os exemplos a produzir uma ordem de inserção previsível. Não presuma que HashSet ou HashMap manterão essa mesma ordem. Para ordenação por chave, outra estrutura ou outra etapa de ordenação pode ser apropriada. Escreva qual ordem o relatório exige.

Em Map, put com uma chave existente substitui o valor associado àquela chave. Se o problema exige recusar duplicados, verifique e trate essa regra em vez de usar put e perder a informação anterior sem perceber. A ausência de uma chave também precisa ser distinguida de um valor nulo quando a implementação permitir ambos.

Nos exemplos, prefira declarar a variável pelo contrato, como List<String>, e criar a implementação que você escolheu. Isso mantém clara a necessidade sem acrescentar uma camada própria de abstração. O tema 11 aprofunda igualdade, hashCode e coleções; aqui, a meta é escolher uma estrutura coerente e usá-la com segurança.

19. Generics, boxing e a armadilha de remover por posição

Uma List<Integer> armazena referências para objetos Integer; generics não recebem diretamente o tipo primitivo int. A linguagem pode fazer boxing ao inserir um inteiro e unboxing ao usá-lo como número. Isso é conveniente, mas uma referência Integer nula pode falhar ao ser desembrulhada. Não trate uma lista de referências como um array primitivo com outra grafia.

Remove com int escolhe a sobrecarga por índice; com Integer, escolhe a remoção por objeto e retira a primeira ocorrência equivalente. Usar remove(10) esperando retirar o número dez pode causar um erro de índice. Leia a assinatura selecionada pela ferramenta ou pela documentação da API, principalmente quando uma classe possui várias sobrecargas.

Arrays.asList oferece uma lista de tamanho fixo apoiada no array: certas alterações de elementos são possíveis, mas adicionar e remover elementos não são. Criar um novo ArrayList a partir dela fornece uma estrutura cujo tamanho pode variar. Também há coleções não modificáveis e cópias que não são necessariamente profundas. Conheça a promessa específica da fábrica ou do construtor escolhido.

20. Iteração, remoção e propriedade dos dados

Alterar estruturalmente uma lista durante um for-each pode invalidar a iteração. Não dependa de uma tentativa que funcionou por acaso com poucos itens. Para remover segundo uma condição, removeIf pode expressar a operação; para um percurso com remoção explícita, use o mecanismo apropriado do iterador. A implementação e o contexto de concorrência impõem limites adicionais.

Uma coleção não modificável por uma referência pode continuar observando alterações de uma estrutura subjacente ou conter elementos mutáveis. Uma cópia independente da lista também pode compartilhar os mesmos objetos. Ao devolver dados de uma classe, diga se o chamador recebe uma visão, uma cópia da estrutura ou uma cópia dos elementos. Não chame tudo de “imutável”.

Para os exercícios de notas e nomes, escolher elementos imutáveis como String simplifica a discussão. Em um cadastro com objetos mutáveis, retome o contrato de igualdade e os limites da cópia. Esses cuidados evitam que uma função aparentemente de consulta altere silenciosamente o estado que outra parte do programa possui.

21. Prática orientada, soluções e revisão dos contratos

  1. Estatísticas: declare as notas 6, 7 e 8 e calcule média, menor e maior. Não inicialize os extremos em zero. Teste depois um array vazio e explique a decisão de recusa.
  2. Busca: procure 4, 9 e 5 em {4, 7, 4, 9}. Imprima a primeira posição ou -1. Não acesse o array pelo retorno sem conferir se encontrou.
  3. Cópia: declare {3, 1, 2}, copie antes de ordenar e mostre as duas sequências. Depois faça uma atribuição simples em uma cópia do exercício para observar o compartilhamento.
  4. Matriz: use {{1, 2, 3}, {4, 5}} e calcule uma soma por linha. O resultado deve ser 6 na primeira e 9 na segunda. Use o tamanho de cada linha.
  5. Lista de inteiros: retire o valor 10 de [10, 20, 10] sem remover pela posição 10. Explique qual sobrecarga será chamada.
Possível solução: somas por linha

A soma fica dentro do laço externo porque cada linha precisa de um acumulador novo. Para uma soma total da matriz, a posição da inicialização seria diferente. O lugar da variável expressa o período durante o qual o estado precisa sobreviver.

Conferir busca, cópia e remoção

As posições são 0, 3 e -1. A sequência original deve continuar [3, 1, 2], enquanto a cópia ordenada fica [1, 2, 3]. A remoção por objeto usa Integer.valueOf(10) e retira uma ocorrência. Se quiser remover todas, esse é outro contrato e pede outra operação.

Avance quando conseguir explicar limites, ausência, ordem, compartilhamento e mutabilidade de cada estrutura usada. O próximo tema concentra dados e operações em classes; essas escolhas continuarão importantes dentro dos objetos.
